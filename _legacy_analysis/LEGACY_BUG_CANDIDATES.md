# 레거시 버그 후보 등록부 (LEGACY BUG CANDIDATES)

> 목적: 현행 레거시(PowerBuilder ERP + SP)에서 **레거시 자체가 틀렸다고 판단되는** 계산/설계 후보를 모아 둠.
> 원칙: 지금은 diff0(레거시 재현)로 맞춰 두고, 각 항목은 **담당 판단 후** "레거시 재현 유지" vs "corrections 등록 후 수정 계상"을 개별 결정.
> 구분: **[레거시오류]** = 레거시 계산이 틀림 / **[nx이관차]** = nx가 레거시와 다름(우리 문제, 레거시가 정답) / **[설계문제]** = 버그는 아니나 정합·유지보수 위험.
> 최종수정 2026-08-13. 근거 스크립트는 `_harness/`.

## A. 원가 SP 계산 — [레거시오류] 후보 (이번 세션 직접 관찰)

### A1. lgroup 필터로 타그룹 제작부품 가공비 누락 ★
- **현상**: 실원가/내부 SP가 가공비를 `CS_M_PROC.ITEM_LGROUP IN(@LS_ITEM_GROUP=최상위품목 lgroup, 'J')` 공정만 계상(R_SORT_SEQ 매칭). 상위품목과 **다른 lgroup 부품의 실제 공정을 0 처리**.
- **근거**: `AGF30058407`(lgroup E) 안의 `AGF30058505`(lgroup G, make_type='1' 사내제작, 실제 BOX 가공공정 868원) → SP GAGONG=0. CS_M_PROC에서 proc 103/104/105는 lgroup 'G' 소속.
- **영향**: 타그룹 제작부품의 실제 발생 가공비를 누락 → 제품원가 과소. 2026-08-13 lgroup-fix로 현재는 **레거시 재현**(diff0).
- **판단 포인트**: BOX 등 타그룹 제작부품 가공비를 제품원가에 포함해야 맞는가(=레거시 버그) vs 별도(그 부품 자체 원가)로 빠지는 게 맞는가(=의도). 사업지식 필요.
- **★실측 결론(2026-08-22)**: 실체=**포장비**(lgroup G 공정=BOX라벨/간지/파레트적재/랩핑/비닐포장/BOX제함/PP Band). 사용자 확인="BOX 제작 안 하나 포장비용 든다". **영향 극소**: 리시빙상위40 중 **포장비 제외 2개**(PQ061203K11·PQ061503K11 각 +238원=실원가 0.4%), 나머지 38개 +0(포장비 이미 자기 lgroup으로 계상). 원인=다른 lgroup의 Package Assembly를 SUB로 품은 특수케이스만 누락. **판정: 실재 버그이나 극소 → 보류**(필터 통째제거는 타케이스 과계상 위험). a1b.txt.

### A2. 임율을 원가시점이 아닌 GETDATE(오늘) 기준 적용 ★
- **현상**: SP가 `CS_M_LABOR_COST_RATE WHERE APPLY_YYYYMM <= CONVERT(VARCHAR,GETDATE(),112)` 최신을 사용 → **원가일과 무관하게 항상 최신 임율**.
- **근거**: SP_CS_견적서(내부용/실원가용) L 서브쿼리 (line ~350).
- **영향**: 1월 원가 계산에 8월 임율 적용 등 **소급/과거 원가 왜곡**. 엔진은 as-of ym이 옳다고 보나 diff0 위해 GETDATE 재현 중.

### A3. 실원가 성분 분해 상쇄 (용접봉을 재료비로 흡수) ★
- **현상**: 용접봉(RAC)을 가공비가 아닌 재료비에 흡수 → **손익 총액은 상쇄로 맞으나 재료/가공 컬럼 분해가 부정확**.
- **근거**: `AJR76523008` 가공비 eng 1666 vs SP 3582인데 총액은 정합(재료비에서 상쇄). 신규는 용접봉=공정종속(proc_weld)로 분리.
- **영향**: 손익 총액만 보면 안 보이나, 재료비·가공비 각 컬럼을 신뢰하면 틀림.

## B. 원가 관련 이중관리/설계 — [레거시오류]/[설계문제]

### B1. 용접봉 BOM+포인트 이중관리 [레거시오류] (corrections.json 등록됨)
- **현상**: 용접봉이 `CS_M_ITEM_BOM` 부자재줄(=포인트×1.5)과 포인트 양쪽에 존재. 값은 ×1.5로 일치하나 어긋날 위험.
- **근거**: `weld_costsource.py`(3품목 정확 ×1.5). 신규=CS_T_ITEM_WELD 포인트 단일소스.

### B2. BOM 3중 분리 + 품번접미사 BOM 복제 [설계문제]
- **현상**: 조달/작업방식마다 품번 접미사로 BOM을 복제(예 `AJR75563402` 6변형). BOM/Routing/Sourcing 3중 분리.
- **영향**: 정합·유지보수 위험(한 변형 수정 시 타 변형 누락). 신규=1품번+1BOM+조달경로 통합.
- **주의**: 변형 SUB "과다전개"(AJR30012xxx 등)는 **[nx이관차]**(nx.bom_line ≠ CS_M_ITEM_BOM, 옆세션 정규화중)이지 레거시 버그 아님 — 레거시 CS_M_ITEM_BOM이 정답.

### B3. 이젠터/사급 오분류 [레거시오류 후보] (corrections.json 등록됨, 담당승인대기)
- `AJR75563402-3-1`(이젠터) make_type 3=매입 → 실측상 유상사급(2=). 사급자식·원소재 유상출고 근거.
- `AJR75563402-4-1`(미래) 등 국내 유상사급 SAGUB_FLAG 누락(=0, 명진/이젠터는 1).

## C. 타 도메인 정산/집계 산식 — [레거시오류] 후보 (프로젝트 이력)

### C1. weight_calc 협력사 원소재 소요량 이중계상
- **현상**: 소요량 이중계상·사급리프·마감기준 오류로 협력사 중량정산 과대(대원 172%, 명진 33%).
- **근거**: 신규 weight_calc 수정 후 대원 172%→1.2%, 명진 33%→0.8%, 6월 개당중량 100% 정합.

### C2. 영업예상매출 20일 과대집계 (pr_t_plan_input 중복)
- **현상**: 20일차 예상매출이 `pr_t_plan_input` 중복으로 과대. 신규는 중복 제거로 총 27.68억.

### C3. 협력사계획 완료수량 = 출하+완제품재고 (실생산 아님)
- **현상**: 완료수량을 fulfillment 출하+완제품재고로 계산(실제 생산량 아님). 당김=CUST_MAINT_DAY 회사근무일·최대발행일=dlvy_day+4.
- **근거**: `_schema/COOP_PLAN_DELIVERY_FORMULAS.md`.

### C4. 재고 배치스냅샷 드리프트 [설계문제]
- **현상**: 수불장·재고장을 단일원장 파생이 아닌 **배치 스냅샷**으로 생성 → 시점 드리프트. 신규=stock_ledger 단일원장 파생.
