## 0. 두 규칙 (한 줄 정의)
- **규칙 A — 재고 가용성 게이팅**: 어떤 차감(출고/소비/키팅/이동)도 **결과 재고가 음수가 되면 거부**. 앞 단계 재고가 없으면 다음 단계 불가.
- **규칙 B — 마감 일자 잠금**: **마감된 기간(≤마감일)의 거래는 생성·수정·삭제 불가**(생산·영업·자재 공통). MASTER 강행옵션은 정책.

## 1. 규칙 A — 재고 가용성 게이팅 (마이너스 원천차단)

### 1.1 단계 체인 (대표 지시 + ★생산 2공정 분리)
**생산은 2가지(PR_M_WORK): P2=가공 · P1=용접.** 따라서 체인은 5단계:
```
자재입고 → 키팅(준비) → [P2 가공] → [P1 용접/조립] → 출고
  └ 입고 안 된 품목은 키팅 불가
     └ 키팅 안 되면 가공실적 안 잡힘
        └ 가공(가공품) 없으면 용접/조립 실적 안 잡힘
           └ 용접(완성품) 없으면 출고 불가
역방향(취소/반품)도 동일 — 결과가 음수면 거부
```
재고점(STOCK_POINT, [[NX_STOCK_LEDGER_DESIGN]]): **MAT(자재) → RDY(준비) → PRD_G(가공품, P2·가공창고 P0001/11라인) → PRD_W/ASY(용접·완성, P1·S계열 라인) → 출하**. 사급=SAG.
- **P2 가공**: 자재(동파이프) 절삭/축관 → 가공품(반제품). 소비=자재/준비, 산출=가공품.
- **P1 용접/조립**: 가공품+부품 용접·체결·검사 → 완성품. 소비=가공품/부품, 산출=완성(ASY).
- 게이팅은 **각 공정 진입 시** 앞 재고점(가공은 자재/준비, 용접은 가공품) 가용검증.

### 1.2 공용 함수 (신설·통일)
```
assert_stock(cur, stock_point, key_dims, need_qty)
  현재고 = 원장 SUM(해당 재고점·품목·[파트/cust])   # nx.stock_ledger 파생 = 기초+ΣMAINT
  if need_qty > 현재고 + 허용오차:
      raise HTTPException(400, f"재고부족 ({품목} 가용 {현재고:g} < 필요 {need_qty:g})")
```
- 차감 쓰기의 **트랜잭션 내, 원장 INSERT 직전** 호출.
- 취소/역거래: 되돌린 뒤 재고가 음수면 거부(동일 함수, need=역수량).
- 현재고 정본 = **nx.stock_ledger STOCK_POINT별 SUM**(컷오버 전 미적재 구간은 레거시 대사로 보강 — [[TRANSACTION_CUTOVER_DESIGN]]).

### 1.3 기구현(참고) — 이미 있는 패턴을 표준으로
- `stock.py`(자재조정/출고): `재고부족 (가용 avail < qty)` 가드 有 → **이 패턴을 공용함수로 승격**.
- `prodwrite.py`(생산자재이동): `FROM파트 재고부족` 가드 有.

## 2. 규칙 B — 마감 일자 잠금 (전 도메인)

### 2.1 마감 단위 (실측 인프라 기준)
- **월마감(전역)**: `nx.stock_close(ym, close_flag)` — 공용함수 `_closed(cur, ymd)`가 이미 판정. **생산·영업·자재 공통**.
- **업체별 마감일**: `MAGAM`/`CM_M_CUST_MAGAM`(JUN_YYMM·JUN_MAGAM_DAY·MAGAM_DAY) — 매입/매출 정산 기준([[newerp-lgsagub-recvcompare]] 등에서 사용).
- **일마감(자재)**: 자재 일마감 스냅샷([[newerp-matclose-movavg]] nx.mat_stock_daily) — 확정일 이하 잠금(추후 연동).
- 레거시 3가드(월말 pu_t_month_stock·수불 pu_t_month_stock_wh·일마감 CM_M_DAILY_MAGAM) → **nx.stock_close/MAGAM로 통합**([[NX_STOCK_LEDGER_DESIGN]] §E).

### 2.2 공용 함수 (통일)
```
assert_open(cur, ymd, domain=None, cust=None)
  if _closed(cur, ymd):  raise HTTPException(400, f"{_ym(ymd)} 마감된 월입니다 — 수정 불가")
  if cust and 업체마감일 >= ymd: raise ...   # 업체별(매입/매출)
```
- **모든 쓰기(생성/수정/삭제)** 진입부에서 대상 일자 검증. 수정/삭제는 **기존 행 일자와 신규 일자 둘 다** 검증.

### 2.3 기구현(참고)
- `_closed(cur, ymd)` = `nx.stock_close WHERE ym` (common.py). 이미 `prodwrite`(생산·자재)·`sales`(매출)에서 호출.

## 4. 균일 적용 계획 (구현 순서 — 승인 후 하나씩)
1. **공용함수 2개 확정**(common.py): `assert_stock(...)`, `assert_open(...)`. 기존 stock.py 재고부족·`_closed` 패턴을 승격·통일.
2. **키팅**(kitting.py cell-confirm): 자재입고(MAT)/준비 재고 없으면 키팅 거부 + 마감잠금.
3. **생산실적 백플러시**(backflush.py): 준비(RDY)/자재(MAT) 없으면 실적 거부 + 마감잠금.
4. **출고/매출**(sales.py·saleout): 완성(ASY) 없으면 출고 거부(재고가드 전면) + 마감잠금 전면.
5. **도입·매입입고**(dopip): 마감잠금(입고는 재고가드 불필요).
6. **마감처리 자체**(purmagam/salemagam): 마감확정 후 해당기간 재편집 잠금.
7. 각 단계 **왕복검증**(정상/부족거부/마감거부) + 취소·반품 역가드.

## 4-B. ★생산 소비 모델 (대표 지시 2026-08-19 — 다음단계 설계·구현)
재고 게이팅(규칙 A)의 **생산실적 단계 소비 정본**. 아래 3가지를 반영해야 마이너스 차단이 정확해짐.

### (1) 생산실적 = 키팅된 것 기준 소비
- 생산실적을 잡을 때 **키팅확인분(RDY)을 소비**한다. 즉 백플러시 소비원천 = 키팅된 수량.
- posting: **−RDY**(키팅 소진) + **−MAT**(실자재) → **+PRD_G(가공)/+PRD_W·ASY(용접완성)**.
- 게이트: 키팅(RDY) 없으면 생산실적 불가 → 앞서 정의한 체인과 일치.

### ★(1-보강) 생산실적 게이트 = 자재재고로만, 키팅과 무관 (2026-08-19 사용자 확정)
**★★확정 규칙 (두 줄):**
1. **자재가 부족하면 생산실적이 잡히면 안 된다** — 자재 현재고 < BOM소요면 실적 **하드 차단**(물리적으로 생산 불가). 마이너스 원천차단.
2. **자재는 있는데 키팅만 안 됐다고 실적을 막으면 안 된다** — 게이트는 **키팅(RDY)을 아예 안 본다**. 자재만 있으면 실적 잡힘. (키팅=flag-only `kitting_cell_confirm` "자재무차감", 준비됨 플래그일 뿐·"키팅 재고" 관리대상 없음.)

⟹ **생산실적 게이트 = 오직 자재 현재고(`_mat_avail`=mat_stock_daily 정본) 기준.** 키팅 상태·RDY원장 무관.

- **구현(backflush.py `_backflush_core`, post)**: BOM 리프별 `소요=cq×prod_qty` vs `_mat_avail`. 부족(관리자재)이면 `return ok:False`("자재부족으로 생산실적 불가"). ★키팅/RDY 조회 없음.
- ★**커버리지 인지**: 자재재고 '관리품목'(mat_stock_daily 존재)만 게이트 — **비키팅품(케이블타이·비닐)·사급포함품(미추적)은 제외**(오차단 방지, §4-C 검증. 8월계획 생산품20 BOM리프217 추적 76.5%·미추적 23.5%=비키팅/사급).
- ★**한계(컷오버 전제)**: mat_stock_daily=레거시 일스냅샷 → **당일 입고분·연속차감 미반영** → 당일 입고 후 실적이면 오차단 가능. **하드 게이트를 실운영 ON 하려면 자재정본을 실시간(기초+당일이동)으로 승격 필요(§4 step4).** 그 전까진 dev 검증.
- ★**−RDY/−MAT 분할 재검토**: 소비 posting은 여전히 '−RDY 우선, 없으면 −MAT'인데 키팅=flag-only면 자재 전량 −MAT이 정합(RDY는 플래그 상쇄만). 게이트(자재재고 full need 검사)는 이미 kitting-independent라 무영향. 컷오버 정리대상.

### (2) 용접봉 등 공정종속 자재 = 공정 소요량으로 별도 차감
- **BOM 소비가 아님**. 용접봉은 **공정 소요량(용접ST × 원단위)**으로 계산해 생산실적 시 **함께 차감**([[newerp-weld-cost-split]]·[[newerp-weld-settlement-roadmap]]).
- 재고점: 용접봉창고(**Q1000**) 또는 자재 − / 협력사정산 연동.
- 게이트: 생산실적 백플러시에 **BOM 자재차감 + 용접봉 공정차감**을 같이 계산. 용접봉 재고 부족도 검증 대상.

### (3) 키팅 안 하는 품목 = 자재→생산창고 직접 이동으로 차감
- **케이블타이·비닐·고무캡** 등 저가/범용 부자재는 **키팅을 안 함**. 자재창고 → 생산창고로 **직접 이동(MV)**하며 재고 차감.
- 키팅(RDY) 단계를 **우회** → 이 품목들은 RDY 게이트 대상 아님, 대신 **자재(MAT) 재고에서 이동출고 시 차감·게이트**.
- 설계필요: 비키팅품 판별 기준(품목분류/플래그?), 이동 시점·수량 산정(생산량×BOM? 수동?), MV posting(−MAT자재/+PRD생산창고).
- → **다음단계에서 상세 설계·구현**(대표 지시).

## 4-C. ★현재고 보강 · 컷오버 안전 (마이그 5단계 — 재고게이트의 전제)
> 재고게이트(규칙 A)는 **정확한 현재고**가 있어야 오차단이 없다. 현재 nx 현재고는 미비 → 아래 순서로 보강·검증 후 게이트 ON.

### 현재 상태 실측(2026-08-19)
- **nx.stock_ledger**: MAT 171,972행(260401~오늘, tag B/S/9/C/5/P/4/2/J/T/1) — **기초(tag3) 없음** → SUM=순변화만(현재고 아님). RDY 12행(웹키팅만), **PRD/ASY 0행**.
- **nx.stock_close_snap**(기초 스냅샷, Phase5): 컬럼 ym·stock_point·item_key·gpc·cust·base/in/out/end_qty — **비어있음**.
- 미러 PU_T_STOCK_MAINT = 라이브 동일 최신(260819) → 델타싱크 가능.
- ★월표기 규칙: **STOCK_YYMM='YYMM' = 그 달의 기말**. 2607=7월기말=8월기초, 2606=6월기말=7월기초. (실측: 2606=4,936M=우리260630, 2607=4,473M=우리260731)

### 정본 현재고 공식 (드리프트 불가)

### ★키팅 게이트 = BOM 부품 기준 (2026-08-19 검증발견)
- 키팅 품목(RDY 원장)은 전부 **ASSY/SUB(분류 110/120, Tube Assembly·Sub Assy)** — **자재(MAT)가 아님**. `_mat_avail(키팅품목)`=0 → 그대로 쓰면 **전 키팅 오차단**.
- 따라서 키팅 게이트 = **"그 ASSY의 BOM 자재 부품들이 입고(자재재고>0)됐는지"**. nx.bom 전개 → 각 자재부품 소요(use_qty×키팅수량) vs `_mat_avail(부품)`. 부족부품 있으면 키팅 거부.
- 이건 [[§4-B (1) 생산실적=키팅기준 소비]]와 연결 — 키팅=예약이지만 부품 가용성은 자재재고로 검증. (BOM 전개 = backflush `_backflush_bom` 재사용.)
- **★검증발견(2026-08-19, 착수보류)**: 개념검증(AJR30019901 10키팅=21부품)에서 ①**일부 ASSY BOM 전개 0종**(AJR30133601 = nx.bom 커버리지 갭) → 게이트 미작동 ②부품 9/21 자재재고0(진짜부족 vs mat_stock_daily 부품커버리지 갭 불명). **지금 켜면 (a)BOM없는 ASSY 무검증통과 (b)갭부품 오차단** → **BOM 전개 커버리지 + 부품 자재재고 커버리지 검증이 선행필수.** 자재게이트처럼 정본이 확실할 때만 ON.

### 마이그 5단계 (각 단계 검증 필수) — ★source 수정 반영
1. **자재(MAT) 기초 심기**: nx.stock_close_snap에 **2607(7월기말) MAT 스냅샷**(PU_T_MONTH_STOCK_WH Z99990) 적재. 자기생성 근거키(ym=2607·point=MAT) 재적재 멱등.
2. **MAT diff0 대조**: `현재고=snap(2607)+Σ원장(≥260801)` == 레거시 현재고(2607+8월이동). 품목별 diff0 검증(허용오차0).
3. **RDY/PRD/ASY 마이그**: 준비(PU_T_READY_STOCK/月마감)·생산(PR_T_MAT_STOCK_WH/月)·완성(SA_T_ITEM_STOCK/月) 기초 스냅샷 적재 + 이동원장 미러. 각 재고점 diff0.
4. **재고게이트 ON**: 현재고 정확 확인 후 `_stock_short_msg`를 현재고공식(기초+델타)으로 승격, 전 차감쓰기점 적용.
5. **컷오버 직전 전 재고점 diff0**: `mirror_recon.py`로 nx파생 vs 레거시 잔량 대조. 불일치=레거시 드리프트로 확인 후 컷오버.

### 이중계상 방지 (핵심)
- 기초=마감월 기말 스냅샷, 델타=**마감월+1 이후 이동만**. 원장이 4~7월 이동을 포함하므로, 현재고 델타는 **MAINT_YMD ≥ (마감월+1)01 필터**로 합산(원장 무삭제·무재베이스).
- 즉 원장은 그대로 두고, **기초는 stock_close_snap·델타는 날짜필터**로 분리 → 이중계상 구조적 불가.
