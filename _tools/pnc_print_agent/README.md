# PNC 프린터 에이전트 — 생산전표출력관리(490) 무음 자동출력

가간판은 **A4 프린터**로, 제품스티커(라벨)는 **라벨 프린터**로 —
직원이 인쇄창에서 매번 고르지 않아도 **발행 즉시 알아서** 나가게 하는 프로그램.

---

## 왜 필요한가

웹(브라우저)은 보안상 "어느 프린터로 보낼지"를 코드로 지정할 수 없다.
그래서 490 화면은 지금까지 인쇄창을 띄우고 **직원이 매번 프린터를 골라야** 했다.
가간판(A4)과 라벨(40×20)이 **서로 다른 USB 프린터**에 물려 있는 현장에서는
한 번만 잘못 골라도 라벨지에 A4 간판이 찍히는 사고가 난다.

⟹ 작업 PC 에 이 프로그램을 상주시키고, **웹은 "가간판이야/라벨이야"만** 알려준다.
   실제 물리 프린터는 **그 PC 의 설정**이 정하므로, PC 마다 프린터 구성이 달라도
   웹 코드는 하나로 유지된다.

```
 [웹 490 발행]
      │  ① 인쇄물 요청 (kind=kanban/label)
      ▼
 [ERP 서버 8010]  /api/print/kanban · /api/print/label
      │  ② PDF(또는 라벨용 TSPL 명령어) 생성
      ▼
 [웹 490]
      │  ③ http://127.0.0.1:17650/print  로 전달
      ▼
 [이 프로그램 — 작업 PC 트레이 상주]
      │  ④ kind 로 프린터 선택
      ├─ kanban ─▶ 가간판 프린터 (210×110 / A4)
      └─ label  ─▶ 라벨 프린터  (40×20)      ← 인쇄창 없이 바로
```

## 설치 (작업 PC)

**exe 하나를 더블클릭하면 끝.** 설치 여부를 스스로 판단한다.

| 상황 | 동작 |
|---|---|
| 처음 실행(USB·공유폴더 등) | `%LOCALAPPDATA%\PNC_PrintAgent` 로 복사 + 시작프로그램 등록 → 자동 재실행 → 안내창 |
| 이미 설치된 PC | 아무것도 하지 않고 그냥 상주(중복설치 없음) |
| 설치됐는데 자동시작만 끊김 | 바로가기만 조용히 복구 |

설치 후 **작업표시줄 오른쪽 트레이 아이콘 → 설정**에서
`가간판·전표 프린터`와 `제품스티커(라벨) 프린터`를 각각 고르면 준비 끝.
다음부터는 PC 를 켜면 자동으로 실행된다. 관리자 권한은 필요 없다.

### 트레이 메뉴
- **설정 / 프린터 지정** — 프린터 2대 지정, 라벨 농도·속도, **테스트출력**
- **로그 열기** — 출력 이력·오류
- **자동시작 해제** — 부팅 시 자동실행만 끔
- **종료**

## 라벨 출력 방식 (설정에서 선택)

| 방식 | 언제 | 특징 |
|---|---|---|
| **TSPL 직송** (기본) | TSC·Bixolon 등 라벨전용 프린터 | 프린터가 QR·글자를 직접 그림 — **가장 선명하고 빠름** |
| **PDF** | 일반 프린터, 또는 TSPL 이 안 맞을 때 | 서버가 그린 이미지를 그대로 출력 |

> 라벨에 **한글(용접사/검사자)이 안 나오거나 깨지면** TSPL 대신 **PDF** 로 바꾼다.
> 프린터 내장 폰트에 한글이 없는 기종이 있다.

## 문제가 생기면

| 증상 | 확인 |
|---|---|
| 화면 상단에 "자동출력 꺼짐" | 트레이에 아이콘이 있는지 → 없으면 exe 재실행 |
| "프린터가 지정되지 않아 인쇄창으로 출력합니다" | 트레이 → 설정에서 프린터 지정 |
| 출력이 안 됨 | 트레이 → 설정 → **테스트출력** 으로 프린터만 따로 점검 |
| 아무 반응 없음 | `%APPDATA%\PNC_PrintAgent\boot.log` · `agent.log` 확인 |

**에이전트가 없거나 실패해도 현장은 멈추지 않는다** —
자동으로 **기존 인쇄창 방식**으로 넘어간다(미설치 PC 는 지금까지와 동일하게 동작).

## 개발자용

```powershell
# 빌드 (개발 PC 에서 한 번만. 작업 PC 엔 파이썬 불필요)
powershell -ExecutionPolicy Bypass -File build.ps1
#  → dist\PNC프린터에이전트.exe  (약 67MB)

# 디버깅
python agent.py --console      # 트레이 없이 서버만, 로그를 화면으로
python agent.py --settings     # 설정창만
```

- 통신은 **127.0.0.1 로만** 바인딩 — 외부에서 이 PC 프린터를 쓸 수 없다.
- 설정·로그 = `%APPDATA%\PNC_PrintAgent\`
- 서버측 인쇄물 생성 = `PNC_ERP_Web/backend/routers/printjob.py`
- 화면측 연동 = `PNC_ERP_Web/js/screens.prod.js` 의 `PRN_AGENT` · `tryAgent`

### API
| 경로 | 용도 |
|---|---|
| `GET /ping` | 생존·프린터 지정 상태(`ready_kanban`/`ready_label`) |
| `GET /printers` | 이 PC 의 프린터 목록 |
| `POST /print` | `{kind, pdf|tspl, doc, copies}` → 출력 |
| `POST /config` | 프린터 지정 변경 |

### 빌드 시 주의(실제로 겪은 함정)
- `--noconsole` 빌드는 `sys.stdout` 이 `None` 이라, 화면에 뭔가 쓰면 **즉사**한다.
  → 파일 상단에서 stdout/stderr 를 빈 통로로 갈아끼운다.
- 설치 때 `taskkill /IM` 로 구버전을 죽이면 **이름이 같아 자기 자신도 죽는다**.
  → `/FI "PID ne <내PID>"` 로 자신을 제외한다.
- 위 둘 다 화면에 오류가 안 떠 원인을 알 수 없다 → `boot.log` 로 어디까지 갔는지 추적.
