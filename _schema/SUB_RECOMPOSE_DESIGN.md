# SUB 재구성·채번·재사용 통합 설계 (SUB_RECOMPOSE)

작성 시작 2026-08-13. 조달경로 통합검토 "신규 조달프로파일(후보) 등록" 모달의 SUB 재편성(공정 바꿔가며 SUB 재구성 + 신규 채번)을 정본화한다.
관련: [[BOM_STRUCTURE_CANON]] · [[R01_REBUILD_DESIGN]] · [[NX_BOM_SCHEMA]] · _migration/sub_norm/NX_MASTER_GAP.md

## 배경 / 문제
- 레거시는 ASSY BOM을 1개로만 구성 → 공정·조달이 다르면 **품번 접미사로 SUB를 복제**(AJR75563402-은납/-19-1/-F&T ...).
- 재설계는 **현행(R01)만 정본 BOM으로 끌고 오고**, 공정이 달라지면 **조달후보(R02/R03)로 신규 등록**. 이때 SUB를 재구성하며 새 SUB를 채번한다.
- 채번을 아무렇게나 하면 **공통 SUB가 중복 생성**되고, 공유 SUB에 변경이 생겼을 때 **일괄 반영이 안 됨**.

## 사용자 확정 결정 (2026-08-13)
- **A) 채번 base = global 순번 레지스트리** (제품 base 아님). 이유: **생성 시점엔 공유 여부를 알 수 없다** → 제품에 묶으면 나중에 "가짜 소속"이 생김. 그래서 **01부터 global 순차**.
- **B) dedup = 완전 차단** + **변경 시 공유 전체 일괄 적용**(참조 모델). 단 **분기(fork)** 탈출구 필수.
- **C) UI = B+C 병행**: 모든 SUB 노드에 재귀 드롭존 + group/ungroup 버튼. 묶는 순간 dedup 발동.

## 1. SUB 정체성 = 구조 시그니처
- **SUB = (정렬된 직속 하위[품번+수량] + 공정[용접봉 포함])** 의 해시.
- **자식이 SUB면 "전개" 아니라 그 SUB의 정본코드로** 시그니처에 포함 → 서브안의서브도 안정·재귀폭발 없음.
- 시그니처 동일 = **같은 SUB = 같은 코드**. (children + welding process 동일이 동일 판정 기준)

## 2. 채번 = global 순번 레지스트리 (nx.sub_registry)
- 코드 = **`S00001`부터 global 순차** (어느 제품에도 안 묶임). 시그니처로 dedup.
- **코드 = 표시** (트리 내 위치표시 `_S01`는 공유 시 제품마다 달라져 불안정 → 금지).
- 형식 = `S`+5자리. **단 기존 실품번에 `S#####` 충돌 없는지 사전검사** 후 확정(있으면 `NS`+숫자 등 접두어로 회피).
- 레지스트리 스키마(초안): `sub_code`(PK, S#####) · `sig`(시그니처 해시, UNIQUE) · `proc`(공정) · `created`, 하위구성은 nx.bom_line/header에 sub_code를 헤더로 저장(참조).

## 3. 생성 시 dedup = 완전 차단 + 강제 재사용
"새 SUB로 묶기(부품 드롭)" 시:
1. 묶음의 시그니처 계산.
2. 레지스트리에서 **동일 시그니처 조회**.
   - **있으면 → 신규 생성 차단**, `"동일 SUB {sub_code} 존재 — 이것을 사용하세요"` → 기존 코드 강제 참조.
   - 없으면 → 신규 채번(`S#####`).
→ 중복 SUB 원천 차단 + 공통 SUB 자동 통합.

## 4. 변경 = 참조 모델 일괄 적용 + 분기(fork)
- **참조 모델**: 부모는 SUB를 코드로 참조(구성 복사 금지) → SUB 편집 = 공유 전 제품 일괄 반영.
- **분기(fork)**: 한 제품만 다르게 하려면 편집이 아니라 "새 SUB 분기" → 시그니처 달라져 **새 global ID 자동 채번**.
- **영향 경고**: 공유 SUB 편집 커밋 전 `"이 변경은 공유중 N개 제품 전체에 적용됩니다"`.
- **편집 후 재-dedup**: 편집 결과 시그니처가 다른 기존 SUB와 같아지면 병합 경고(자동병합 금지).

## 5. UI (조달후보 모달) — B+C
- **부품풀**: 부품 + (필요 시) 기존 SUB. **모든 SUB 노드가 자기 `＋ 새 SUB로 묶기` 드롭존을 이미 보유** → "레벨 추가" 단계 없이 그 자리에서 nested SUB 생성.
- 드롭존은 **부품 + 트리에 이미 있는 노드(부품·SUB)** 를 받음 → 기존 SUB 노드를 상위 존으로 드래그하면 그것을 감싸는 상위 SUB 생성(bottom-up, 서브안의서브를 같은 드래그로).
- **group/ungroup 버튼**: 다중선택 묶기/풀기(대량·실수복구 보완).
- 묶는 매 순간 **#3 dedup 발동**.

## 6. 검증 — 품번 변경이 전 프로그램에 무해함을 보장
- **대원칙: 표시-only 우선.** 정본코드는 표시 매핑, **데이터(nx.bom_line.child_item)는 raw코드 유지** → 원가·소요·중량·견적 무영향. (실측 2026-08-13: bom_line/header에 `_S` 0건, sub_alias는 bom.py 1곳만 참조=표시용)
- **데이터 변경 불가피 시(참조교체·통합·편집전파)**: 백투백 diff0 게이트 — 원가(엔진vs레거시SP 97.5% 무회귀)·소요(PR 0건차)·중량·견적·BOM트리·backflush·전엔드포인트 스모크(500 0). 기존 하네스(_harness/cost_oracle) 재사용.
- **편집 전파 시**: 영향받는 전 제품 diff0 재검증. **백업·롤백** 스크립트 필수, 컷오버 재적용 대상 등록.

## 7. 원가 세션 연동 (경계면) — 2026-08-13
> **★스코프 분리(사용자 2026-08-13)**: **용접봉 관련(bom_line 소비재 정밀식별·삭제·원가 diff0 判定)은 옆 세션(원가)이 정리.** 본 sub_norm 세션은 **"서브 이름 정형화"에만 집중** = `S#####` 채번·시그니처 dedup·표시 정본화(display-only, bom_line/proc_weld 불변). 시그니처의 proc_weld 성분은 **원가세션 확정을 그대로 참조**(우리는 용접 데이터를 건드리지 않음).

옆 세션(원가 분석)과 직접 물리는 지점. **남은 가공비 갭의 다수 = 원인 A(변형 SUB) = nx.bom_line 구조문제**(엔진 아님). 본 SUB 정규화가 정답이며, 엔진 수정(B lgroup + direct5)과 **직교·상호보완** → 합치면 가공비 diff0 ~100% 전망. 갭 대상 예: AJR30012xxx · AJR74482401 · AJR77224002.
- **(가) RAC(용접봉) 경계 — ✅확정: 신규 ERP = proc_weld 방식** (2026-08-13 사용자). 용접봉은 bom_line child 아님. 시그니처의 "process" 성분(proc_weld)으로만 반영, 재고/정산도 공정종속.
  - **⚠️정정(2026-08-13, 원가세션 정밀실측 채택)**: 제 이전 "bom_line 용접봉 19품번·193행 = 이중계상"은 **이름기반 과다분류**(is_weld가 RAC/BCUP/3H008 prefix + 'Solder/용접봉' name으로 너무 넓게 잡음 — '아르곤 용접'·'은납 30%'·"+용접"조립SUB까지 포함, 진짜 소비재 아님). **잘못된 진단.**
  - **정확한 사실(원가세션)**: `proc_weld.weld_item = RAC 14품번뿐`(BCUP/은납 없음). **`bom_line ∩ proc_weld.weld_item = 0`** → **proc_weld↔bom_line 직접 이중계상 없음**. 엔진은 bom_line에서 **RAC% 만 skip**.
  - **미결(원가세션 진행)**: 진짜 용접봉 소비재(RAC/BCUP/은납/인치링)를 **정밀 식별**해, bom_line에 남은 그 행들을 **삭제 시 엔진 원가가 바뀌는지 判定** 중. 결과 나오면 시그니처의 children 제외경계도 여기 맞춰 확정.
- **(나) 정규화 후 재검증 — 필수**: 엔진은 nx.bom_line을 그대로 읽으므로, **데이터레벨 정규화 완료 시 `cost_oracle` diff0 게이트 재실행**(그들 구조 + 엔진 B/direct5 정합 확인). = 설계 #6과 동일 게이트.
- **⚠️ 이력주의**: 과거 **CS강제정합 → 롤백(원가훼손)** 사고([[newerp-nxbomline-single-bom]]). 이번엔 **스코프 한정**(변형SUB dedup만, CS_M_ITEM_BOM 전체치환 아님) + RAC 경계 정확 + diff0 게이트 통과를 전제로만 데이터변경.
- ※ 주의: 본 설계의 **표시-only 레지스트리/dedup은 가공비를 못 바꿈**(bom_line 구조 불변). 가공비 갭 해소는 **데이터레벨 변형SUB 정규화**(설계 #6 "데이터 변경 불가피" 경로)라야 효과 → 원가세션과 함께 진행·검증.
