# 용접봉 데이터 정합 개선 — 추후 과제 (item_weld ↔ proc_weld divergence)

> 상태: **미착수 · 추후 계획적으로**. 사용자 지시(2026-08-28): "레거시 BOM 잘못된 부분 많아 개선하고 싶다. 시간 걸려도 **정확하게**. 성급한 일반화 말고." → 이번엔 기록만, 별도 스레드로 진행.
> 다른 세션·개발자용 durable 기록. 관련: WELD_PROC_TABLES_SPEC.md · WELD_RING_DESIGN.md §27 · [[newerp-weld-cost-split]]

## 1. 문제 (실측 2026-08-28)

용접봉 소요가 **두 곳에 저장**되는데 **어긋난 품목이 많음**:
- **① 관경별 횟수** = `nx.item_weld` (Ø6.35 몇 번 등) — 팝업 입력·표시값
- **② 소요량(use_qty)** = `nx.proc_weld` — 원가엔진이 읽는 정본

정상 = ①로 계산(Σ std_use×횟수×1.5) == ②. 그러나 어긋남:

| 유형 | 전체 | **활성(최근12개월)** | 문제 |
|---|---|---|---|
| 값 다름 (①≠②) | 537품목 | **231품목** | 관경 재계산 소요량 ≠ 저장 소요량 |
| 관경 없음 (②만 있음) | 997품목 | **414품목** | proc_weld엔 use_qty 있으나 item_weld 관경 0 |
| **합계** | **1,511** | **635** | |
- proc_weld 활성 2,566행 중 일치 1,904 / 어긋남 635품목. meta_ok=0 = 1,095행.

## 2. 근본 원인 (기록)

proc_weld·item_weld가 **두 레거시 소스에서 따로 이관**됨(WELD_PROC_TABLES_SPEC §9):
- **proc_weld.use_qty = CS_M_ITEM_BOM 화면값**(원가 SP가 읽는 정본).
- **item_weld = CS_T_ITEM_WELD 관경 그리드**(견적 입력).
- 두 레거시 소스가 원래 다름(371노드~) → 이관 후에도 divergence. **414 관경없음 = 그리드 미입력인데 원가 BOM엔 소요량 존재.**

## 3. 왜 중요 / 왜 지금 안 함

- **용접봉 %유형 팝업 편집 시**: 팝업이 item_weld(관경) 불러와 저장 시 proc_weld를 관경으로 재계산 → **무편집 저장인데 원가 변동**(예 AJR73980318 0.0234→0.0156). 안전 편집의 선결.
- **지금 안 하는 이유**: 635품목(414는 관경 새 입력 필요·use_qty에서 역산 불가) = 대형. **용접봉 %유형 기능에 끼우면 데이터 늪.** 분리(사용자 확정).

## 4. 추후 정확한 접근 (성급한 일반화 금지)

1. **전수 정밀 진단**(표본 아님): 231 값다름 = 오라클(CS_M_ITEM_BOM SP, pncind 실행)로 **어느 게 진짜 맞는지** 품목별. 414 관경없음 = 관경 원천(견적그리드·현장) 확인.
2. **품목 유형별 정합 규칙** 확정: 관경 재계산 vs 원가값 중 정본. 414는 관경 **사람 입력**(자동 역산 불가).
3. **정합 도구 = 용접봉 %유형·다종 팝업**(오늘 백엔드 `weld/save_node` 구현·검증 완료). 각 BOM 열어 담당이 정확히 관경·유형 입력 → 그 품목 정합. **사람 검증 = 일반화 아님.**
4. **원가 변동 = 등록된 교정**(하드룰5 승인된 버그수정만 예외). 레거시 원가가 틀렸던 것 바로잡기 = cost_oracle/COST_DESIGN_DIFFS 등록.

## 5. 이미 된 것 (도구 준비완)
- `weld/save_node`(cost.py) = 용접봉 다종 원자 저장. 검증완(2종 저장). 이게 정합 입력 도구.
- weld_type_map(1/2/3/5/30% × 봉/와이어/링) = %유형 매핑. `weld/types`(활성 18종) API로 노출.
- 재고 차감(backflush)이 proc_weld 다종 지원 → 정합 후 자동 정확.
- **★다종 %유형 팝업 = 완성**(2026-08-28, feat/weld-issue-analysis): 조립공정 팝업(품목BOM관리)의 관경별 용접이 유형별 다종 매트릭스([+유형추가]·은납 proc28 자동제안). loadNaeProc **roll=0(노드 자체값)** 편집.
- **★★divergence 안전장치 = `save_node` verbatim 원상보존**: 관경 무변경 유형은 기존 proc_weld/item_weld/routing을 그대로 복원(재계산 안 함) → **divergence 노드(proc_weld 결측·중복 routing 포함)도 무편집 저장 원가 diff0**. 검증완(ADM73210516: RAC30599330 proc_weld 결측·중복 routing까지 diff0). ∴ **담당이 아무 BOM이나 열어 %유형만 지정·저장해도 원가 안 틀어짐** — 정합작업이 "관경 실제 편집한 유형만" 재계산되므로 대량 진단 없이도 안전하게 하나씩 교정 가능.

## 6. 남은 (이 과제 착수 시)
- 프론트 다종 매트릭스 팝업(LOAD=weld/get·SAVE=weld/save_node) + 현재 관경/소요량/어긋남 표시.
- 635 전수 진단 산출물(품목별 원인·정본판정).
- 품목별 정합·오라클 diff0(또는 등록교정) 게이트.
