## 2. ★부수 발견 — 응답은 성공인데 아무것도 안 들어가는 결함

검증 중 발견했습니다. `matrecv_receive` 에 **품번을 다른 키 이름으로 보내면**:

```
      응답: {'ok': True, 'count': 1}          ← 성공이라고 답한다

       —     ①원장 stock_ledger(MAT)          +0.00
       —     ②잔액 PU_T_MAT_STOCK_WH          +0.00
       —     ③미러이력 PU_T_STOCK_MAINT        +0.00   ← 아무데도 안 들어갔다
```

`stock.py:616` 이 `r.get("item")` 을 읽는데, **품번이 빈 문자열이어도 검증을 통과**합니다
(`nx.item` 조회가 빈 값으로 나가 미등록 판정도 안 걸림). 그리고 INSERT 는 되지만
빈 품번이라 어느 집계에도 안 잡힙니다.

⟹ **화면에는 "입고 완료" 가 뜨는데 재고는 안 늘어납니다.** 사용자가 원인을 알 방법이 없습니다.
`if not item: 오류` 한 줄이면 막힙니다.

**자기 자신과 비교**하게 됐습니다.

```python
kitting.py:40     _PSCH = "..._TEST3.nx" if _src=="live" else "..._TEST3.nx"
live_api.py:938   _S    = "..._TEST3.nx" if _live      else "..._TEST3.nx"
sales.py:1387     SCH   = "..._TEST3.nx" if src=="live" else "..._TEST3.nx"
```
**사용자가 "레거시로 대사" 를 눌러도 같은 값이 나옵니다.**

⚠ `sales.py:1388` — `cn = _conn() if src=="live" else _nx()` : 스키마는 같은데
**커넥션만 RO/RW 로 갈립니다.** 조회 화면이 쓰기가능 커넥션을 잡습니다.

`kitting.py:187-202` 는 **동일 쿼리를 두 번** 실행, `:233-242` 는 **자기 자신과 FULL JOIN** —
최소 6곳이 **결과는 맞지만 DB 부하만 2배**입니다.
