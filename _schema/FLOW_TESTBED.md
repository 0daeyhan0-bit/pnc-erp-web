## 1. 무엇을 하는가

**우리가 개발한 프로그램(화면)이 부르는 실제 API 를 그대로 호출해서**
① 값이 원장·수불장·재고 **3곳에 같은 값으로** 적히는지,
② 우리가 세운 **시스템 규칙(음수·마감·권한·유효성)이 실제로 막는지**
를 한 번에 검증한다. 단순 흐름만 보지 않는다 — 규칙이 같이 돌아야 시스템이다.

정적 분석(grep)으로 결론내지 않는다. **구동 결과가 근거다.**
(2026-08-28 실측: grep 으로 "미러 미반영"이라 보고했던 결함 F1·F2 는 실제 구동에서 전부 정상이었다.)

## 2. 오염 0 원리 — 왜 실DB 에 대고 돌려도 안전한가

`flow_server.py` 는 **일반 백엔드와 같은 app** 을 띄우되, 기동 직전에
`common._nx` / `_nx_tx` 를 **no-commit 공유 커넥션**으로 몽키패치한다(실측 102곳).

| | 동작 |
|---|---|
| 화면 → HTTP → 라우터 → DB쓰기 | **전 경로가 실제로 실행된다**(가드·채번·미러반영 포함) |
| `commit()` / `close()` | **no-op** — 어떤 호출도 확정되지 않는다 |
| 종료 시 | `/api/_flow/rollback` → 기동시점 행수와 대조해 **불변 증명** |

즉 "진짜로 돌리되 아무것도 남지 않는다". 매 실행마다 오염 0 을 **증명**하고 끝난다.

## 3. 쓰는 법 (다른 세션·다른 개발자)

```bash
# 창 1 — 롤백 모드 백엔드 (기본 8099. 다른 사람과 겹치면 --port 로 바꾼다)
python _migration/flow_server.py --port 8099

# 창 2 — 검증
python _migration/flow_scenarios.py              # 전체
python _migration/flow_scenarios.py --list       # 케이스 목록만(실행 안 함)
python _migration/flow_scenarios.py --kind R     # 규칙만
python _migration/flow_scenarios.py --only 키팅   # 이름에 '키팅' 들어간 것만
python _migration/flow_scenarios.py --port 8098
```
종료코드 = FAIL·미구현이 있으면 1, 전부 통과면 0 (CI 에 걸 수 있다).

**동시에 여러 세션이 돌릴 때는 포트를 나눈다** — 8099/8098/8097 …
서버 하나에 공유 트랜잭션 하나이므로 **한 서버를 둘이 같이 쓰면 서로의 미커밋을 본다.**

없는 엔드포인트는 404 → **SKIP** 으로 보고한다(‘차단’으로 세지 않는다 — 막지도 않았는데 PASS 가 되면 안 된다).

**실측 기준선(2026-08-28, 같은 케이스 28건을 두 브랜치에서 실행)**

| 브랜치 | PASS | FAIL | 미구현 | SKIP |
|---|---|---|---|---|
| `main` | 21 | 1 | **3** | 3 |
| `feat/close-mgmt` (PR #97) | **28** | 0 | 0 | 0 |

main 에서 뜨는 미구현·FAIL 은 하네스 오류가 아니라 **main 에 아직 그 규칙이 없다는 사실**이다.
PR #97 이 정확히 이것들을 채운다:

| main 판정 | 내용 |
|---|---|
| ☐미구현 | 자재 쓰기 **마감기간 잠금 없음** — 마감월 전표가 그냥 저장된다 |
| ☐미구현 | 키팅 **마감기간 잠금 없음** |
| ☐미구현 | 공정별생산실적 **자재부족 차단 없음** — 자재 없이 실적이 잡힌다 |
| ★FAIL | 백플러시 차단 사유에 **축별 보유가 없다**(`가용 -240 < 소요 …` 만) — 규칙 A-0-1 미충족 |

★즉 이 TestBed 는 **"우리 규칙이 이 브랜치에 실제로 들어와 있는가"를 재는 자**이기도 하다.
  main 에 병합될 때마다 돌려서 숫자가 내려가지 않는지 본다.

### 3-1. 내 프로그램을 검증에 추가하는 법 — `flow_cases.py` 에 dict 하나

```python
# 흐름: 값이 제대로 적히는가
dict(kind="F", name="자재입고 (자재입고관리)", method="POST", path="/api/stock/save",
     body=lambda ctx: {"screen":"receipt","user":"flowverify",
                       "rows":[{"MAINT_YMD":YMD,"MAT_CODE":ctx["mat"],"qty":100}]},
     probe="원장MAT", delta=+100, mirror=True),

# 규칙: 제대로 막는가 (거부 + DB 무기록 이어야 PASS)
dict(kind="R", name="자재출고 — 가용 초과 차단", method="POST", path="/api/stock/save",
     keyword="재고부족",
     body=lambda ctx: {...}),
```

| 키 | 뜻 |
|---|---|
| `kind` | `"F"` 흐름 / `"R"` 규칙 |
| `path` | **화면이 실제로 부르는 그 경로** (js 에서 `grep "/api/"` 로 찾는다) |
| `body` | dict 또는 `lambda ctx: dict` — `ctx` 는 픽스처 결과 |
| `probe` | 관측 이름(`flow_server.PROBES` 키). 없으면 `PROBES` 에 추가 |
| `delta` | 기대 증감 |
| `mirror` | `True` 면 수불장·재고까지 **3곳 일치** 요구(자재 계열) |
| `keyword` | (규칙) 거부 사유에 들어갈 말. 달라도 거부되면 PASS — 참고용 |
| `skip_if` | `lambda ctx: bool` — 픽스처가 없으면 SKIP |

**참조할 실데이터가 필요하면** `FIXTURES` 에 `(키, SQL, 반영함수)` 를 추가한다.
★픽스처는 **쓰기 시작 전에** 전부 읽고 커서를 닫는다(§6-2 이유).

**새 관측 지점이 필요하면** `flow_server.py` 의 `PROBES`(일자 스코프) 또는
`PROBES_MAT`(품번 스코프)에 한 줄 추가한다. 전 테이블 집계는 금지 — 느려서 못 돈다(§6-5).

### 3-2. 규칙을 만들면 케이스도 같이 만든다 (하드룰)
게이팅 캐논 §0-★ = **예외 없음 + 사유 고지**. 새 규칙을 코드에 넣었으면
`flow_cases.py` 에 `[R]` 케이스를 **같은 커밋에** 추가한다. 규칙은 검증과 함께 산다.

### 3-3. 판정 읽는 법
| 표시 | 뜻 |
|---|---|
| `✅ PASS` | 흐름=값 일치 / 규칙=거부 + DB 무기록 |
| `★FAIL` | 흐름=값 불일치 / 규칙=거부했는데 **DB 에 기록됨** |
| `☐미구현` | 규칙이 **막지 못했다** — 막아야 할 것이 통과 |
| `– SKIP` | 픽스처 부족(참조할 실데이터 없음) |

## 6. 하네스를 만들며 실측한 함정 (재발 방지 — 그대로 밟지 말 것)

1. **`app.mount("/", StaticFiles)` 뒤에 등록한 라우트는 404** — `/openapi.json` 에는 보여도 호출이 안 된다. 제어 라우트를 `app.router.routes` **맨 앞으로** 옮겨야 한다(CLAUDE.md §2 와 같은 함정).
2. **쓰기 시작 뒤 별도 커넥션으로 `nx.stock_ledger` 를 읽으면 무한 대기** — 자기 자신의 미커밋 잠금에 걸린다. 하네스가 2분·10분 타임아웃 나던 진짜 원인. → **픽스처는 전부 쓰기 이전에 읽고 커서를 닫는다.** 자기가 쓴 행을 봐야 하면 `/api/_flow/sql`(공유 커넥션)로 읽는다.
3. **롤백 검증도 같은 함정** — 롤백 *전에* 별도 커넥션으로 COUNT 하면 멈춘다. → 기준 행수는 **서버 기동 시점**에 잡는다.
4. **`io.TextIOWrapper(sys.stdout.buffer,…)` 재래핑은 `python -u` 를 무력화**한다(블록 버퍼 → 진행상황이 안 보임). `line_buffering=True` 필수.
5. **프로브를 전 테이블 집계로 두면 못 돈다** — 스텝마다 170만 행 COUNT. 테스트 스코프(일자·품번)로 좁히면 빠르고 오히려 정확하다.
6. **`INSERT_USER_ID` 는 `'web'` 하드코딩** — payload 의 `user` 는 원장에 안 남는다. 테스트 행을 사용자로 못 거른다(수량으로 특정할 것).
7. **`_migration/*` 는 gitignore** 였다 → `!_migration/flow_*.py` 예외 등록(과거 scratchpad 하네스 소실 사고와 같은 조건이었다).
8. **화면을 playwright 로 열려면 로그인 오버레이를 통과해야 한다** — `#lg-id`/`#lg-pw`/`#lg-login` (admin/1234).

## 8. [S] 인증 · 소속 강제 케이스 신설 (2026-08-29) — **PASS 83 · FAIL 0 · 오염 0**

### 왜 새 종류가 필요했나
기존 `[R]` 은 **"막혔는가"** 만 본다. 소속 강제는 그것으로 판정할 수 없다 —
협력사가 남의 코드를 넣으면 **200 이 나오되 자기 데이터만** 나와야 하기 때문이다.
`[R]` 로 짜면 "차단되지 않음 = 미구현" 으로 잘못 보고된다.

⟹ **`[S]` 종류**를 만들었다. 기대 상태코드 + **실제 응답값 검사**를 함께 본다.
```python
dict(kind="S", name="...", method="GET", path="...", as_="miraero",
     expect=200,                                   # 기대 HTTP 상태
     check=lambda res, ctx: (True, "실제 관측값"))  # 화면에 그대로 찍힌다
```
`as_` = 로그인할 계정(None 이면 무토큰). 하네스가 `/api/auth/login` 으로 실제 로그인해
토큰을 붙인다 — **인증을 붙인 뒤로는 하네스도 로그인해야 검증이 된다.**

### 실행 결과 — 사용자가 실제로 겪는 그대로

**① 로그인 전에는 아무것도 안 보인다**
```
무토큰 협력사 계획조회 / 송장목록 / 입고실적 / 입고스캔  →  401 로그인이 필요합니다
★무토큰 계정목록  →  401        (예전에는 평문 비밀번호 12개가 그대로 나왔다)
```

**② 로그인**
```
옳은 비밀번호        200  슈퍼관리자 · 유효 12시간
틀린 비밀번호        401  아이디 또는 비밀번호가 올바르지 않습니다. (남은 시도 4회)
★없는 계정          401  아이디 또는 비밀번호가 올바르지 않습니다.   ← 같은 문구(존재 여부를 흘리지 않는다)
```

### 하네스 자체도 손봤다
| 무엇 | 왜 |
|---|---|
| `ROLLBACK_TABS` 에 `app_user`·`app_session` 추가 | 하네스가 로그인하면 세션이 생기고 실패하면 잠금이 걸린다. 없으면 "오염 0" 이 계정 테이블을 **안 본 채로** 통과한다 |
| `delta()` 방어 신설 | `flow_server._probe` 는 쿼리가 실패하면 `None` 을 넣는다. 러너가 `None - None` 으로 죽어 **멀쩡한 케이스를 거짓 FAIL** 로 만들었다 |
| `call(..., token=)` · `token_for()` | 인증을 붙인 뒤로는 하네스도 로그인해야 한다 |

### ★실행 중 겪은 함정 (§6 에 추가)
**서버 하나에 실행은 한 번.** `flow_server` 는 `0.0.0.0` 에 바인딩한다.
`netstat | grep 127.0.0.1:8098` 로 죽이면 **안 죽는다.** 그래서 앞 서버가 살아남고,
롤백이 끝나지 않은 **더러운 트랜잭션 위에서 두 번째 실행**이 돌아
`close/anomaly`·`close/ledger` 가 500, 프로브가 `None` 을 뱉었다.
**코드 문제가 아니었다** — 깨끗한 서버로 다시 돌리니 전부 PASS.
⟹ 죽일 때는 `grep ":8098 "`(인터페이스 무관)로 잡고, **바인드 오류가 0인지 로그로 확인**한 뒤 돌린다.

### 하네스 계정 (★운영 전 반드시 바꿀 것)
`flow_cases.ACCOUNTS` 에 개발 시드 계정이 있다(환경변수 `FLOW_PW_*` 로 덮어쓸 수 있다).
화면(브라우저)에는 비밀번호가 더 이상 실려 나가지 않지만, **하네스는 로그인해야 하므로**
자격증명이 필요하다. **컷오버 전에 시드 비밀번호를 바꾸고 환경변수로 넘긴다.**
