## 1. 무엇을 하는가

**우리가 개발한 프로그램(화면)이 부르는 실제 API 를 그대로 호출해서**
① 재고 흐름이 원장·수불장·재고 **3곳에 같은 값으로** 적히는지,
② 우리가 세운 **시스템 규칙(음수·마감·권한·유효성)이 실제로 막는지**
를 한 번에 검증한다. 단순 흐름만 보지 않는다 — 규칙이 같이 돌아야 시스템이다.

정적 분석(grep)으로 결론내지 않는다. **구동 결과가 근거다.**
(2026-08-28 실측: grep 으로 "미러 미반영"이라 보고했던 F1·F2 결함은 실제 구동에서 전부 정상이었다.)

## 2. 오염 0 원리 — 왜 실DB 에 대고 돌려도 안전한가

`flow_server.py` 는 **일반 백엔드와 같은 app** 을 띄우되, 기동 직전에
`common._nx` / `_nx_tx` 를 **no-commit 공유 커넥션**으로 몽키패치한다(실측 102곳).

| | 동작 |
|---|---|
| 화면 → HTTP → 라우터 → DB쓰기 | **전 경로가 실제로 실행된다** (가드·채번·미러반영 포함) |
| `commit()` / `close()` | **no-op** — 어떤 호출도 확정되지 않는다 |
| 종료 시 | `/api/_flow/rollback` → `RAW.rollback()` → 기동시점 행수와 대조해 **불변 증명** |

즉 "진짜로 돌리되 아무것도 남지 않는다". 매 실행마다 오염 0 을 **증명**하고 끝난다.

**제어 엔드포인트**(이 서버에만 존재)
`POST /api/_flow/scope` 관측 스코프(일자·품번) · `POST /api/_flow/mark` 기준점 ·
`GET /api/_flow/probe` 델타 · `POST /api/_flow/sql` **미커밋 조회**(SELECT 만) ·
`POST /api/_flow/rollback` 롤백+증명

## 5. 생산실적 게이트 — 예외 제거 완료 (2026-08-28)

대표 지시: **"생산실적도 막아라. 우리 시스템은 예외가 없다. 대신 왜 안 되는지 알려줘라."**
정본 규칙 = `STOCK_GATING_CLOSE_LOCK_RULES.md` **§0-★**.

| 경로 | 전 | 후 |
|---|---|---|
| `_backflush_core` | `_tracked()` 예외로 **소비대상 자식의 70.2%(6,988/9,955) 무판정 통과** | 예외 제거·전수 판정 |
| `/api/procreg/save` 공정별생산실적 | 게이트 **없음**(INSERT 만) | 마감잠금 + 자재가용 + 사유 |
| `_is_inner_prod` 로 대상 필터 | 라이브 커넥션에서 `nx.item` 조회 실패 → **예외를 삼키고 False** → 게이트 스킵 | 필터 제거. BOM 전개 결과로만 판정 |

판정축 = **실제 소비축**(RDY 준비재고 → MAT 자재재고). 생산창고(`PR_T_MAT_STOCK_WH`)는
소비축이 아니므로 가용에 넣지 않되 **사유에 실어** 어디 있는지 알린다.
성능: 자식마다 3쿼리 → `_avail_bulk` 로 **축당 1쿼리**(500건 청크). 하네스 전체 35초.

★설계상 "해당 없음"(예외 아님): 키팅은 flag-only 로 **차감이 없다** → 게이트 대상이 아니다.
  "차감이 없어서 해당 없음"과 "차감이 있는데 안 막음"은 다르다. 후자는 금지.

## 6. 하네스를 만들며 실측한 함정 (재발 방지)

1. **`app.mount("/", StaticFiles)` 뒤에 등록한 라우트는 404** — `/openapi.json` 에는 보여도 호출이 안 된다. 제어 라우트를 `app.router.routes` **맨 앞으로** 옮겨야 한다. (CLAUDE.md §2 와 같은 함정)
2. **쓰기 시작 뒤 별도 커넥션으로 `nx.stock_ledger` 를 읽으면 무한 대기** — 자기 자신의 미커밋 잠금에 걸린다. 하네스가 2분·10분 타임아웃 나던 진짜 원인. → **픽스처는 전부 쓰기 이전에 읽고 커서를 닫는다.** 자기가 쓴 행을 봐야 하면 `/api/_flow/sql`(공유 커넥션)로 읽는다.
3. **롤백 검증도 같은 함정** — 롤백 *전에* 별도 커넥션으로 COUNT 하면 멈춘다. → 기준 행수는 **서버 기동 시점**에 잡는다.
4. **`io.TextIOWrapper(sys.stdout.buffer,…)` 재래핑은 `python -u` 를 무력화**한다(블록 버퍼 → 진행상황이 안 보임). `line_buffering=True` 필수.
5. **프로브를 전 테이블 집계로 두면 못 돈다** — 스텝마다 170만 행 COUNT. 테스트 스코프(일자·품번)로 좁히면 빠르고 오히려 정확하다.
6. **`INSERT_USER_ID` 는 `'web'` 하드코딩** — payload 의 `user` 는 원장에 안 남는다. 테스트 행을 사용자로 못 거른다.
7. 하네스는 `_migration/*` gitignore 에 걸려 있었다 → `!_migration/flow_*.py` 예외 등록(과거 scratchpad 하네스 소실 사고와 같은 조건이었음).
