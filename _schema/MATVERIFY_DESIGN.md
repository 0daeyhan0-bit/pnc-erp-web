## 목적(사용자)
- **국내+해외 협력사 모두 관리.** 수입은 **리드타임 때문에 과매입 경향** → 확인 필요. 국내 협력사도 같이 확인.
- 입고 수량을 100% 검수 못하니, 실적 대비 과입고 업체/품목을 찾는다.

## ★★모델 재정의 (2026-08-22, 사용자 확정) — 소요 vs 매입
> 이전 "매입−실제소비(가공출고)" 산식으로 좁혔던 것 폐기. **소요량(필요) 대비 매입 차이**가 본질.
- **소요량** = 얼마나 필요했나 = **리시빙(LG 입고) 실적 + 직거래(매출 거래처) 실적 × BOM 전개**. (원래 요청 "리시빙 실적+직매출 기반")
- **매입** = 실제 매입 입고(업체별, 국내+수입).
- **차이 = 매입 − 소요량**: **과매입**(매입≫소요=진짜 과매입, 수입 리드타임) / **덜매입**(매입≪소요→대부분 BOM 과다전개 문제지만 검증대상). **차이 큰 품목 위로 정렬, 과매입·덜매입 다 검증.**
- 수불장(정본)으로 재고 현실 대조. ★단가 산식 우회(vendor단가·flow보정 등)는 금지 — 수량 basis로 검증.

## ★★★소요 엔진 순차 검증 결과 (2026-08-23) — 실측 완료
검증 기간 2601~2608, 절삭협력(ct=6) 타겟. BOM 전개 = nx.CS_M_ITEM_BOM(except_flag<>1, 검증엔진), 타겟(협력사부품)에서 정지.
1. **소요 소스 = `SA_T_SALE_DTL`(전체 출하, FINISH_FLAG='0') × BOM** — LG+직거래 완전 포함, **이중계상 없음**. ★리시빙(SA_T_LG_RECEIVING_DTL)은 매출(출하)의 **LG 부분집합**(998품목 겹침·966=97% 수량동일). → 리시빙+매출 합산 금지, **SALE_DTL 하나가 정답**. (매출ITEM=완제품 70%, 한 WORK_ORDER의 다품목=별개 완제품·BOM자식 겹침0=사전전개 아님).
2. **소요 정확도 = 86% 일치**(소요/소비 0.8~1.25), **중앙값 1.00**. 소요≈소비≈매입(통과품). → 엔진 건전, 쓸 만함.
3. **소비 정의 = 가공출고(tag B)**. 사급출고(5) 추가는 악화 → **B가 맞음**.
4. **★outlier(~14%)는 대부분 BOM 데이터 문제**(구매행위 아님. base폴딩·사급출고로 해소 안 됨):
   - **과다(6~7%, 소요≫소비)** = **BOM 과다전개**. 예 MJU63509919 소요73,632 vs 소비40·매입40 / MJU47146603 소요28,956 vs 4. (매입도 적음 → 덜매입 아님, BOM이 안 쓰는 부품 대량계상).
   - **과소(6~7%, 소요≪소비)** = **BOM 미전개**. 예 AJR52676202 소요10 vs 소비26,135 / MJU66997203 소요1 vs 소비1,019. (BOM이 실제사용 누락).
5. **★진짜 과매입 신호 = 매입 vs 소비(실제 가공출고)** — BOM소요 아님. 절삭협력 2014품목 중 **56품목(3%)이 매입≫소비**(과매입후보). 예 MJU63711305 매입24,560·소비0 / MJU66478801 매입25,033·소비7,194(71%초과). ('샘플' 등 비자재 제외 필요).

## ★★★소요 정확도 = BOM 구조 대조 (2026-08-23) — "완벽 가능?" 실측
사용자 질문: 소요 정확도 완벽 구현 가능한가? (많은 곳에서 쓸 정본). 신규 ERP BOM을 간결화(1품번1BOM)함.
- ★내 이전 검증 오류 자백: `CS_M_ITEM_BOM` + `except_flag<>1` **단순 traversal = 재료비BOM·검증엔진 아님**. 검증된 소요=STEP5-7(`nx.plan_part_mat` 99.955% vs 레거시). 단 그것도 PLAN기반+BOM데이터 잔차(rawmat-soyo 95.4~101.5% 업체별 튐).
- **클린 `nx.v_pr_bom`(1품번1BOM) vs 실제소비(가공출고B) 대조**: exact 87%·base 87%(중앙값1.00). ★**심함과다(>5) 절반 감소**(레거시CS 44→클린 22 exact, 37→15 base) = 변형SUB 이중계상이 구조적으로 줄어든 증거. 사용자 직관(간결구조) 정확.
- **남은 outlier(~13%) 원인 = 분류/데이터 정확도**(구조도 규칙도 아님):
  - 과다(동관 SGROUP130, 예 5210A22034A 소요16,422 vs 소비84): **유상사급(LG제공→우리 가공출고 없음)** 또는 **변형 letter(A/B) 미통합**(base가 dash없는 suffix 못 접음).
  - 과소(SGROUP110/130, 예 MJU66570404 소요11 vs 소비13,894): **except_flag로 제외됐으나 실제 소비**(MJU66570404=CS_CALC_EXCEPT_HANDOFF 사례!) 또는 BOM 미전개.
- ★**결론(완벽 가능?)**: ①레거시 소요 재현=이미 완벽(99.955%). ②소요=실제필요 완벽매칭=**구조(클린BOM)는 필요조건, 충분조건 아님**. 충분조건=**플래그/분류 정본화**(사급여부 SAGUB·except_flag·유상사급 동관·변형 letter통합). 구조는 이중계상(최대오차) 제거로 풀렸고, 남은 last-mile=데이터 큐레이션. ③★ground-truth 주의: 소비=가공출고(B)만으론 **사급/LG제공 부품엔 부정합**(그건 우리 가공출고 안 거침) → 완벽대조엔 소비=가공출고+사급소비+LG제공분 필요.

## ★★★설계 결론 (검증 기반)
- **과매입 판정 신뢰기준 = 매입 vs 실제소비(가공출고 B)**. BOM 소요는 신뢰선 아님(outlier=BOM노이즈).
- **BOM 소요의 용도 = ①86% 품목 소비 교차검증 ②outlier=BOM 오류 플래그**(덜매입=BOM과다전개 / 과소=BOM미전개). 사용자 "덜매입은 BOM문제" 실측 확인.
- **3열(소요·소비·매입) 병렬 표시**로 구분: 매입≫소비&≫소요=진짜과매입 / 소요≫소비≈매입=BOM과다전개 / 소요≪소비=BOM미전개.
- 재고 현실 대조는 협력사SUB=PR(생산파트)재고(자재수불장 PU엔 통과0).

## ★★수불장(자재재고) 검증 결과 (2026-08-22)
정본 자재 수불장 = 레거시 **`w_pu_stock_260`(자재일별수불현황)**, SP=**`SP_PU_CALC_ALL_STOCK`**.
1. **자재창고(Z99990/IS0001) 전용 PU 재고**만 계산. 소스 union: 매입입고 + **도입-구매(수입 `pu_t_stock_maint_c` division='P')** + 재고조정(tag2) + 재고이동(PU_T_STOCK_MOVE) + 자재출고(tag1,4,5,6,8,A,B,J) + 도입-판매(_C division='Q'). → **수입은 정본 로직에 포함**(자재창고 버킷 조건 하).
2. **전체 재고 = PU(자재) + PR(생산파트) + SA(영업)** 합산(SP outer: PU_STOCK_QTY+PR_STOCK_QTY+SA_STOCK_QTY). **협력사 SUB 부품(AGR30801601 등)은 자재수불장(PU)엔 통과(0), 실제 재고는 PR(생산파트)** → 자재수불장만으론 협력사SUB 재고 안 보임(1차대상 유의).
3. **단가 방식 차이(★)**: 레거시=**단일 단가(최종매입가/표준)로 기초·입고·출고·재고 일괄평가**(기초 재평가, 화면상 한 품목 단가 전부 동일). 우리 nx.mat_stock_daily=**이동평균**(기초 이월, 단가 거래마다 진화, 사용자 확정). → **수량 basis 동일, 금액만 방식차** = 과입고 수량검증 무영향, 금액 대조 시 감안. [[newerp-matclose-movavg]]
4. **우리 nx.mat_stock_daily 검증 상태**: 수량 100%·금액 99.95%(vs 레거시), 우리버그3 수정(수입 환율·마이너스재고 폭발·tagP), 레거시버그 플래그. **수입 환율 반영됨**. 단 PU(자재창고) 범위.
- ★결론: 수불장은 수입을 무시하지 않음(정본 SP·우리 nx 모두 포함). AGR30801601 수입이 자재수불장에 안 뜬 건 **그게 PR(생산파트) 재고 품목**이기 때문. 협력사SUB 과입고 재고대조는 PR 수불장 필요.

## ★핵심 모델 = 실측 자재 수불 (BOM 소요 추정 폐기)
```
순증(재고변화) = 매입입고 − 가공출고(실소비) − 사급출고 ± 조정   [전 공급원 실측]
순증이 크게 양수 = 산 것보다 안 쓰고 재고로 쌓임 = 과입고 후보
```
- **태그 확정**(PU_T_STOCK_MAINT): 매입=9자재입고/S세트입고/C가공이동입고/G축관입고/H가공입고 (+수입=PU_T_STOCK_MAINT_C DIVISION='P') · **가공출고이동=B(=실제 생산투입 소비)** · 사급출고=5 · 조정=1,2 · 생산입고=P(우리생산).
- 순증 = Σ(전 태그≠3) + 수입. = 진짜 재고변화(전 공급원).

## ★왜 BOM 소요가 아니라 실측인가 (내가 처음에 틀렸던 것)
- 처음엔 "리시빙×BOM=소요 vs 매입"으로 접근 → **틀림.** ①`nx.bom_line`은 평탄화·변형SUB로 **3배 과다전개**([[newerp-lme-overcount-rootcause]]) ②정지규칙·사급중단·용접봉제외 등 안 지킴.
- 검증된 소요 엔진은 **STEP5→6→7 `nx.plan_part_mat`**(PR `v_pr_bom`, 사급중단=PART_DTL 보유, charindex 중복컷, 최하위집계, 용접봉RAC제외, prod_rate) = 레거시 99.955%. 단 PLAN 기반.
- 결정적: **실제 소비는 `가공출고(tag B)`.** BOM 소요는 계획 추정일 뿐. 과입고=실측 재고순증이 정답. (예 AJR30077403: BOM추정으론 과입고로 오판됐으나 실제 가공출고 147,451로 재고 0 소진 = 과입고 아님)

## ★공급원(supplier) 분해 — 다소스 정확 귀속
- 한 품목을 **여러 곳이 공급**(국내 협력사 + 수입). 순증은 전소스라, 업체별 귀속엔 **공급원 전체 분해 필수**.
- 각 품목 vendors[] = 국내 협력사(CUST_TYPE→_CT_NAME 태그) + 수입(_C, kind='수입', XINXIANG/AUDY/FONE THAI 등) + 기타(비협력 PU 집계).
- 매입유형(ct)은 **"이 유형 매입이 있는 품목" 필터**(엄격 스코프 아님). ct='IMP'=수입 전용 뷰.

## ★발견 (실측 결과)
- **과입고(재고순증)는 대부분 수입에 집중**: AGR30801601=XINXIANG(수입)25,600/명진(협력)4,199 · AJR30125601=AUDY(수입)61,990/둔안12,507 · AJR30073601=FONE THAI(수입)23,500/대원1,279. → **리드타임 과매입 = 수입** 사용자 가설 실측 확인. 국내 협력사는 상대적 균형.
- **서포터(AJJ) = 체결 루프 순증0**(과입고 아님): 대원 부품 매입(9)→가공출고(B) 상쇄 + 우리 생산입고(P)→사급출고(5) 상쇄. 순이동 0.

## ★함정·교훈 (레거시 데이터 튐 — 사용자 반복 경고)
1. **집계 단정 금지.** 품목별 스파이크 많음 → 순증 나열 + **이상치 플래그만**, 사람이 검토.
2. **단가불명 가드**: 소량매입(buy<10)이면 단가 스파이크(예 "파이프 수불정산" 2개→13B) → 순증액 산정 제외.
3. **base 정규화(변형코드 통합) 함정**: `-SUB`(체결 SUB)는 **조달변형이 아니라 별개 품목** → 병합 금지(서포터 순증 오산). 숫자 조달경로 접미사(-3-1/-4-2/-20-1)만 병합. sub_variant_map(검증) 우선, 없으면 첫 '-' 앞 폴백. 커버리지 14% 미완 부채(원가·소요 공통).
4. **소비는 전 변형코드에서 base로 집계**(매입코드≠소비코드 갈림). type6-매입코드로만 스코프하면 소비 과소→가짜 과입고.
5. **수입(_C)은 전 공급원 합산해야 순증 정합**(netmv는 PU만이라 수입 별도 가산). 단가=외화×환율.

## ★재고 = 정본(자재일마감 이동평균) 사용 — 스냅샷 저장 안 함 (2026-08-22 결정)
- 사용자: "정본으로 하자." → **matverify는 재고 스냅샷을 저장/관리하지 않고, 회사 정본을 조회만**(read-only).
- **정본 = 자재일마감 이동평균 `nx.mat_stock_daily`**(matclose 산출, 검증 99.95%). 실재고=정본기말(ROW_NUMBER 최신 ymd≤to), 기초=정본기초(최신 ymd<fr), **정확코드→base 폴딩 합산**. carry-forward라 이동 없는 날도 최신 스냅샷 유지.
- _conn(live)에서 **cross-DB** `PARTNER_ERP_TEST3.nx.mat_stock_daily` 직접 읽힘(확인). 커버 967/973(절삭협력, 2608). 미커버=정본 미추적 품목(소량) → 실재고 "-".
- ★**왜 자체계산 폐기**: 자체 전이동누적(PU 전태그+수입)은 **세트입고(S)/가공출고(B) 내부루프까지 포함**→정본과 grain 달라 값 상이(예 MJU62916126: 자체 39,895 vs 정본 15,142 vs 자재수불장 자재창고 1,342). 혼란 유발. netmv(순증)만 실측 유지.

## ★순증액 = 정본 재고금액증감 (2026-08-22, vendor 송장단가 튐 제거)
- 사용자 "첫번째 품목이 과한것 같아"(AJR30125601 순증액 188M) 조사 → **근본원인=변형코드 혼합 + 완성세트 단가 튐**.
- base `AJR30125601`(+9변형)이 성격 다른 변형을 합침: **-3-2=이젠터 완성조립품(세트입고 42,000원, 정본 자재재고 미추적=생산품)** + **-A-S-1~6=AUDY 수입부품(1,689~5,309원)** + -3-1(30,700)+-20-*(7,950~17,500). vendor 송장 블렌드단가 20,506/ea에 완성세트가 끌어올려 순증액 과대(188M).
- **해결**: 순증액을 vendor단가×순증 대신 **정본 재고금액증감(=off_end_amt − off_beg_amt, mat_stock_daily.stock_amt 폴딩)**으로 산정. AJR30125601: 188M→**39.5M**(정본 일치). 완성세트(-3-2)는 정본 자재재고에 없어 자동 배제, 실제 보유 수입부품재고만 정본가로 평가. 정렬키도 이 값.
- 미커버(정본 미추적, 소량)만 vendor 추정단가 폴백(+단가불명). 순증액 컬럼명→**재고증감액**(순증 qty 아닌 재고증감의 금액이므로).
- ⚠남은 검토: -3-2(완성세트)와 -A-S-*(수입부품)를 같은 품번으로 폴딩하는 게 맞나(조달경로差면 유지, 완성/부품 다르면 분리) = 사용자 판단 대기. 단 재고금액증감 방식은 이 폴딩 여부와 무관하게 올바른 금액(정본재고 기준).

## 컬럼(화면) — 수불장 형태(그룹 헤더)
좌 마스터=공급처(협력/수입/기타 유형태그) → 우 상세(2단 헤더):
`품번·품명·기초 | [입고] 협력사·타협력사 | [출고] 가공·사급·직납·조정 | 순증·재고증감·재고증감액·실재고·비고·공급원(전체)·흐름`
- **기초/실재고/재고증감/재고증감액** = 정본(자재일마감). 기초=정본기초(<fr), 실재고=정본기말(≤to), 재고증감=실재고−기초, **재고증감액=기말금액−기초금액**. 미커버=null→"-".
- **입고**: 협력사(선택 마스터업체 매입) / 타협력사(그 외 전 공급처=총매입−협력사, 수입 포함).
- **출고**: 가공(순소비=가공출고B−직납) / 사급(tag5) / **직납**(=리시빙分, 가공출고 내 분리→이중차감 없음) / 조정(1,2).
- **순증(실측)** = 총매입 − 가공 − 사급 − 직납 + 조정 (전 공급원 실측 재고변화). ★grain 다름→기초+순증≠실재고(정본). 순증은 재고증감과 대조용.
- 흐름유형: 직납 / 사급재출고형 / 수입주도 / 다업체소싱 / 컴포넌트(가공소비).
- 플래그(비고): **순증과다**(유의순증 & 정본재고증감액>3M=실제 쌓임) / **재고미확인**(유의순증 & 정본커버 & 재고증감<순증0.5=통과/타창고) / **정본미커버**(유의순증인데 정본 미추적) / **재고음수**(정본재고<−100) / 소비없음 / 사급>매입 / 단가불명(미커버 폴백). ★순증 유의성=수량기준(net>매입×0.2 & >50, 단가튐 무관).
- 기간=일자(date) 범위, 기본=당월1일~당일. 페이지 세로스크롤 없음(flex 내부스크롤·2단 sticky헤더).
- ★검증: AGR30801601 순증 12,822=실재고 12,822(XINXIANG 수입 과입고가 재고로 쌓임 확인). AJJ서포터 순증0.
