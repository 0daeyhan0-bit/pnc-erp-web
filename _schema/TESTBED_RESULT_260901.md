### ① routing_edge 싱크를 돌릴까요  (E12)

**증상**: 자재소요의 작업처가 옛 업체로 남아 있다. 39행.

```

케이비  (2266)  +96,768      ← 웹은 여기로 보낸다
                             수량 합계는 정확히 일치. 업체만 뒤바뀜.
```

**원인**: 소요의 작업처는 **BOM 이 아니라** `nx.routing_edge.wc` 에서 온다.

```
planrev._step7_sql :  ov_wc = ISNULL(routing_edge.wc, 마스터)
routing_edge       :  wc = COALESCE(wc_user, wc_live)
                      wc_live ← nx.item 에서 시드
```

`nx.item` 은 라이브와 **불일치 0**(최신)인데 `wc_live` 만 낡았다.
`wc_user`(사람이 편집한 값)는 **0건** — 아무도 손대지 않았는데 값만 옛것이다.

**조치**: `POST /api/routing/sync` 한 번. 39행이 전부 해소된다.
사용자 편집(`wc_user`)은 보존되므로 안전하다.

update/delete 에만 그 처리가 빠져 있었습니다.

**수정**: `stock.py _mat_mirror_edit` 버킷키 일원화 (수불장 전표엔 원 거래처 유지)

