# 조달후보 상세 편집 (SUB 재구성·공정 배치) 워크플로우 — 정본 스펙

> 화면: 개발 > 조달경로 통합검토 > (대안 더블클릭) 조달후보 상세 편집.
> 목적: 현행(R01)을 복사/신규로 만든 Rnn 후보의 **BOM 구조를 SUB 단위로 재구성**하고 라인별 **구분(생산구분 5종)**을 지정. 업체·단가는 조달프로파일(별도).
> 이 문서 = **정확한 구현·검증의 기준**. 현재 코드가 이와 다르면 = 버그(§7).

---

## §1. 데이터 모델 (nx.sourcing_route_line)
- **node_kind**: `SUB`(중간 조립단위) / `PART`(부품 leaf).
- **parent_line**: 이 라인이 속한 SUB의 line_id. `NULL`=ASSY 레벨0 직속.
- **staged**: `1`=보관함(왼쪽 풀·미배치) / `0`=배치됨(ASSY레벨0 or SUB 소속).
- **gubun**: 생산구분 5종 — 제작/외주/구매/사급/외주직납. (SUB에도 지정 = 그 SUB 성격)
- **sub_item / child_item**: SUB이면 sub_item=SUB코드, PART이면 child_item=부품코드.
- 계층: ASSY(레벨0) → SUB(parent_line=NULL) → 중첩SUB(parent_line=상위SUB) → PART(parent_line=소속SUB or NULL).

## §2. 상태
- **view**: 현행(baseline·R01) 읽기전용.
- **fresh**: 신규 미커밋 드래프트(가져오기 방금 생성·[등록] 전). 닫기/취소=삭제(롤백).
- **edit**: 기존 Rnn 후보 편집. 닫기=스냅샷 복원(롤백)·저장=확정.
- ★R01(route_no=1)=수정잠금(저장버튼 없음·PR#48).

## §3. 불변식 (INVARIANTS — 저장 게이트가 강제)
1. **부품수 = BASE 부품수** (RAC 용접봉 제외). 미배치/누락/초과 0.
2. **공수합 = BASE 공수합** (절삭 + 조립). |차| < 0.5.
3. **staged = 0** (보관함 미배치 부품 없음).
4. **SUB 멤버 정합**: PART.parent_line = 실재 SUB.line_id.
5. **용접봉(RAC*) 제외**: 부품셋·공수합에서 빠짐(공정종속 자재).
6. ★**seed 부품셋 = BASE 부품셋** (복사 직후 무편집이면 게이트 통과해야 함). ← **현재 위반(버그#4)**.

## §4. BASE 정의 (검증 기준선)
- BASE = 대상품목의 "구조적 평면 부품셋 + 공수합". 
- ★핵심 결정: BASE는 **구조 기준**(전 BOM 부품)이어야 하는가, **재료비 기준**(재료비>0)이어야 하는가?
  - 현재 `_base_flat_lines`=재료비>0만 → 재료비0 부품 누락.
  - 복사 seed `_route_baseline_lines`=v_cs_bom 전부품 → 재료비0 포함.
  - **불일치 → 버그#4.** 스펙 결정 필요: **부품셋 검증은 구조 기준으로 통일**(재료비0 부품도 정당한 BOM 구성).
