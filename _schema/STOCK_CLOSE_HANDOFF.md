# 재고·마감 도메인 인계 — 다른 세션이 읽고 작업하기 위한 문서

> 작성 2026-08-27 · 작성자 = **재고/마감 도메인 담당 세션**
> 목적: 다른 세션(용접봉·BOM·원가 등)이 재고·마감을 건드릴 때 **방향이 어긋나지 않게** 하기 위함.
> 이 문서는 **방향·정본·금지·미결**만 담는다. 상세는 각 캐논 링크.

## 1. 질문에 대한 확답 — **마감 스냅샷은 과도기다 (영구 모델 아님)**

다른 세션에서 *"옆 세션(=재고/마감)이 마감-스냅샷을 정본으로 강화 중인가, 아니면 과도기로 보는가"* 를 물었다.
**답: 과도기다. 종착점은 영구재고(실시간 원장)이고, 그건 이미 캐논에 적혀 있다.**

정본 공식 — `_schema/STOCK_GATING_CLOSE_LOCK_RULES.md` §4-C:

```
현재고(point,item) = 기초(확정 마감스냅샷, 직전 마감월) + Σ stock_ledger(마감월+1 이후)
```

이게 곧 영구재고 모델이다. **마감스냅샷은 기초 앵커일 뿐, 수량의 상시 정본이 아니다.**
같은 문서의 마이그 5단계 4번 = *"재고게이트를 현재고공식(기초+델타)으로 **승격**"*.
`DO_NOT_USE_FIELDS.md` §16 마지막 줄도 *"수렴(컷오버): stock_ledger 실시간 정본 승격 + 스냅샷 은퇴"*.

### 1-1. 그런데 왜 지금은 `mat_stock_daily` 를 쓰는가
이유는 딱 하나 — **`nx.stock_ledger` MAT이 병행운영 중 미동기화라 45% 불일치**이기 때문이다(실측 근거는 §16).
"정본이라서"가 아니라 **"원장이 아직 못 믿을 상태라서"** 쓰는 다리다.

### 1-2. ★오해 정정 — 재설계는 스냅샷 강화가 **아니라 그 반대**다
다른 세션이 *"옆 세션이 mat_stock_daily 를 정본으로 강화 중"* 이라고 본 것은 오해다.
이번 마감 재설계가 한 일은:

- **(전)** 마감 = `nx.mat_stock_daily`(임시 빌더 산출물)를 **복사**해 확정
- **(후)** 마감 = **전표(`PU_T_STOCK_MAINT` 등 원장 원천)에서 직접 파생**해 확정

즉 임시 빌더 의존을 **끊는** 작업이다. 파생이 diff0 나는 순간 **빌더와 `mat_stock_daily` 는 불필요해진다** = 스냅샷 은퇴.
현재 `mat_stock_daily` 는 **검증용 대조본(oracle)** 으로만 쓰고 있다.

## 2. 지금 이 순간 지켜야 할 결선 규칙 (컷오버 전)

다른 세션이 재고를 건드릴 때 **이대로만 하면 충돌 없다.**

| 항목 | 지금 쓸 것 | 근거 |
|---|---|---|
| **자재(MAT) 가용판정·게이트** | `common._mat_avail()` (= `nx.mat_stock_daily`) | `DO_NOT_USE_FIELDS.md` §16 |
| 준비/사급/생산/완성 잔량 | `nx.stock_ledger` (`RDY`/`SAG`/`PRD`/`ASY`) — **유일 소스, 정당** | 동 §16 예외 |
| 생산(가공/용접) 가용 | `common._prod_avail(item, line)` | 게이팅 캐논 §4-C 표 |
| 완성/제품 가용 | `common._finished_avail(item)` | 동 |
| **웹 쓰기(−출고/복원)** | `nx.stock_ledger` 에 posting | `NX_STOCK_LEDGER_DESIGN.md` §4 |
| 마감 잠금 확인 | `common._lock_msg()` / `_assert_open()` | `CLOSE_MGMT_CANON.md` |

**즉 "게이트는 `mat_stock_daily`, 쓰기는 `stock_ledger`"** 가 현재 정답이다.
용접봉도 예외 없이 이 규칙을 따르면 된다 — 이 조합은 지금 재고/마감 도메인이 진행 중인 재설계와 **충돌하지 않는다.**

### 2-1. ★음수재고 = **경고 아니라 차단** (대표 확정, 재론 불가)
대표 지시 원문(2026-08-27 세션):
> *"경고후 차단이 맞아"* · *"우리 차단 규칙은 전 부서에 동일하게 적용될거야"*
> *"그건 출고 입고 반품에 모두 동일하게 적용되면 음수가 되는 경우는 막아야해"*

구현 = `common._neg_stock_msg(cur, item, delta, point, label)` — `delta<0` 이고 `avail+delta<0` 이면 **차단(HTTPException 400)**.
"현장 안 멈추게 경고로 시작" 은 **일반론이지 PNC 결정이 아니다.** 신규 차감 지점은 이 함수를 쓴다.

## 4. ★미결 — 자재 단가 회계방식 (대표 결정 대기, 결정 전 마감 배포 보류)

**이건 원가에 직결되므로 다른 세션도 알아야 한다.**

### 4-1. 사실관계
- **수량**은 우리 파생본이 레거시와 99.9~100% 일치 = **해결**.
- **단가**는 우리(빌더·파생 **공통**)가 레거시를 재현하지 못한다:

| 대조 | 수량 | **단가** |
|---|---|---|
| 빌더 `260630` vs 레거시 2606 (**시드 지점**) | 100.00% | 98.63% |
| 빌더 `260731` vs 레거시 2607 (한 달 굴린 뒤) | 100.00% | **78.00%** |
| 파생 `260731` (기초=레거시2606) vs 레거시 2607 | 99.92% | **80.17%** |

기존 기록에 있던 *"mat_stock_daily == 레거시 월마감 100%"* 는 **수량만**의 이야기였다.
`260630` 의 98.6% 는 빌더가 레거시를 시드로 받은 자리라 당연한 것이고, 한 달 굴리면 78% 로 떨어진다.

### 4-2. 원인 = 회계방식이 다름
레거시 월마감 정본 = **`src_extracted/sa_stock_01/w_pu_stock_160.srw`** (`DELETE`+`INSERT INTO pu_t_month_stock_wh`).
레거시는 **이동평균이 아니라 총평균법(월별 가중평균)**:

```
STOCK_COST = (BASIC_AMT + INPUT_AMT) / (BASIC_QTY + INPUT_QTY)     ← 월 1회
```

| # | 항목 | 레거시 | 우리(빌더=파생) |
|---|---|---|---|
| 1 | **평균방식** | **총평균법**(월 1회) | **이동평균**(입고 건건) |
| 2 | 입고 tag | `3,9,C,G,H,S,P,R` | `9,S` 만 |
| 3 | 검사 미통과 제외 | `NOT(insp_flag IN('S','F') AND insp_proc_flag<>'1')` | 없음 |
| 4 | 수입 금액원천 | `PU_T_STOCK_MAINT_C.TAXPAYERS`(과세표준) | `MAINT_AMT × EXCHANGE_RATE` |
| 5 | 소모품 제외 | `ISNULL(ITEM_SGROUP,'') < '990'` | `ITEM_SGROUP LIKE '99%'` |
| 6 | 품목마스터 조인 | `JOIN PR_M_ITEM`(없으면 탈락) | 없음 |

(출고 tag `1,4,5,6,8,A,B,J` · 반납 `T` · 조정 `2` 로 레거시는 명시 분류. 우리는 "전 tag 부호합" → **수량 결과는 동일**이라 100% 맞았다.)

### 4-3. 선택지
- **(A) 레거시 총평균법 재현** — 원가 diff0 하드룰과 정합. 일마감 단가는 근사치가 됨.
- **(B) 이동평균 유지** — 주류 ERP(SAP moving average V)·실시간 원가에 맞음. **원가 diff0 깨짐.**
- **(C) 분리** — 회계용 월단가 = 레거시 총평균(diff0) / 운영용 일단가 = 이동평균. 둘 다 저장. ← 담당 세션 권고

**다른 세션에 주는 함의**: 자재단가(`avg_cost`)를 원가·정산에 쓰는 코드는 **이 결정 전까지 `mat_stock_daily.avg_cost` 를 "레거시와 일치한다"고 가정하지 말 것.** 수량은 믿어도 된다.

## 5. 확정된 규칙 (변경 금지)

- **마감 = 확정(freeze) + 잠금.** 일마감 ⊂ 월마감. 해제 = 스냅샷 제거 + 잠금 해제 + 로그.
- **소급은 재개방이 아니라 당월 소급조정.**
- **잔량 0 품목은 스냅샷에 적재하지 않는다** (대표 확정 2026-08-27). 음수는 실재고이므로 유지.
  레거시도 `HAVING SUM(...)<>0` 으로 전부 0인 행을 배제 → 규칙 정합.
- **마감 실행/해제는 트랜잭션**(`_nx_tx`) — 스냅샷만 커밋되고 잠금이 실패하면 고아행이 남는다(실제 사고 2,342행).
- **쓰기 전 잠금 확인 필수**: 재고 이동을 쓰는 신규 엔드포인트는 `_assert_open(cur, ymd, "MAT", "자재출고")` 를 먼저 호출한다.

## 7. ★수불장 설계방식 (2026-08-27 추가 — 옆 세션 착수용)

### 7-1. 한 줄 요약
**수불장은 원장이 아니라 "확정 스냅샷(기초) + 그 기간 전표(이동)"의 파생 뷰다.**
저장하지 않고 **매번 계산**한다. 그래서 드리프트가 구조적으로 생길 수 없다.

```
기말 = 기초(직전 확정 스냅샷) + 입고 − 출고 ± 조정
       └ nx.stock_snapshot           └ 전표(PU_T_STOCK_MAINT 등) 를 tag 로 분류
```

### 7-2. 불변식 (모든 재고점 공통 · 어기면 버그)
```
기초 + 입고 − 출고 ± 조정 = 기말
```
- **전 품목 균일 적용.** 어떤 부품도 특별관리하지 않는다(`CLAUDE.md` §1-8).
- 화면별 조정(adj) **부호 규약이 다를 수 있다** — 반드시 그 화면 규약으로 검사할 것:
  - 생산 480 : `기말 = 기초 + 입 − 출 **+** 조정`
  - 제품 040 : `기말 = 기초 + 입 **−** 조정 − 출`
  같은 식으로 검사하면 오탐 난다(실제로 SAL 19건 오탐 겪음).

### 7-3. tag 분류 = 레거시 정본 (`w_pu_stock_160.srw`)
자재(MAT) 기준. **이 분류가 수불장의 축이다.**

| 구분 | tag | 비고 |
|---|---|---|
| **입고** | `3, 9, C, G, H, S, P, R` | 검사 미통과분 제외: `NOT(insp_flag IN('S','F') AND insp_proc_flag<>'1')` |
| **수입 입고** | `PU_T_STOCK_MAINT_C` `DIVISION<>'Q'` | 금액 = **`TAXPAYERS`(과세표준, 이미 원화)** — `MAINT_AMT×환율` 아님 |
| **수출 출고** | `PU_T_STOCK_MAINT_C` `DIVISION='Q'` | |
| **출고** | `1, 4, 5, 6, 8, A, B, J` | |
| **생산창고 반납** | `T` | 부호 반전 |
| **재고조정** | `2` | |
| 제외 | `ITEM_SGROUP >= '990'`(소모품) · `PR_M_ITEM` 미등록 | 레거시 `WHERE`/`JOIN` 동일 |

★ 우리가 예전에 쓰던 "매입 = tag `9,S` 만" 은 **틀린 축약**이었다. 위 8개가 정본.

### 7-4. 단가 = 총평균법 (대표 결정 2026-08-27)
```
STOCK_COST = FLOOR(STOCK_AMT / STOCK_QTY)          ← 월 1회 확정
STOCK_QTY  = BASIC_QTY + INPUT_QTY - OUTPUT_QTY + TRANS_QTY
STOCK_AMT  = BASIC_AMT + INPUT_AMT - OUTPUT_AMT + TRANS_AMT
```
- **기간 = 역월 1개월.** 이동평균은 **은퇴**.
- **일마감** = 수량만 확정, 금액은 **직전 월확정 단가로 평가**(총평균법 표준).
- 구현 = `routers/close.py` `_ta_build()` / `_snap_mat_month()` / `_snap_mat_day()`.
- 검증기 = `_migration/legacy_total_avg_verify.py` (읽기전용).

### 7-5. 재고점(STOCK_POINT)별 소스 — 지금 무엇을 읽어야 하나

| 재고점 | 수불장 소스 | 상태 |
|---|---|---|
| **MAT** 자재 | 전표 `PU_T_STOCK_MAINT`(+`_C`) + 확정 스냅샷 기초 | ✅ 총평균 구현·검증 |
| **PRD** 생산 | `live_api._prodstock` (레거시 480 재현) | ✅ 스냅샷 확정 diff0 |
| **SAL** 완성 | `live_api.salesstock` (레거시 040 재현) | ✅ 스냅샷 확정 diff0 |
| **RDY** 준비 · **SAG** 사급 | `nx.stock_ledger` (유일 소스) | 스냅샷 미구현 |

→ **PRD/ASY 는 사실상 비어 있다.** 원장으로 생산·완성 수불장을 만들 수 없다(그래서 위 recipe 를 쓴다).

### 7-6. 지금 화면이 읽는 것 (전환 예정)
`live_api.matledger`(자재수불장)는 아직 **레거시 임시테이블**을 읽는다:
- 월 = `PU_T_MONTH_STOCK_WH`
- 일 = `PU_T_MONTH_STOCK_WH_DAILY` ← ★**레거시 `w_pu_stock_260` 이 조회할 때마다 `TRUNCATE` 하는 임시테이블**

즉 **일자 수불장은 "누가 언제 조회했느냐"에 따라 내용이 바뀐다.** 이게 C7(수불장을 확정 스냅샷 기반으로 전환)의 이유다.
→ **신규 수불장·재고 화면은 이 두 테이블을 새로 참조하지 말 것.** `nx.stock_snapshot` + 전표로 파생하라.

### 7-7. 새 수불장/재고 화면을 만들 때 지켜야 할 것
1. **기초는 반드시 확정 스냅샷에서** — `nx.stock_snapshot(domain, ptype, period, item_code, loc)`.
   레거시 잔량테이블(`PU_T_MAT_STOCK` 등) 직복사 금지(드리프트 있음).
2. **이중계상 금지** — 기초는 확정 시점, 델타는 **그 다음날부터**. 날짜필터로 분리한다.
3. **품목키는 항상 `UPPER(LTRIM(RTRIM()))`** — 레거시는 CI 콜레이션이라 `동Body`/`동BODY` 를 한 품목으로 합친다. 파이썬 dict 는 안 합쳐서 수량이 갈라진다(같은 사고 3회).
4. **잔량 0 은 스냅샷에 적재하지 않는다**(대표 확정). 음수는 실재고이므로 유지.
5. **쓰기 전 잠금 확인** — `common._assert_open(cur, ymd, "MAT", "자재출고")`.
6. **음수 차단** — `common._neg_stock_msg()`. 경고 아니라 **차단**(대표 확정).
7. **마감된 기간의 전표는 바꾸지 않는다.** 레거시는 마감 후에도 원장이 바뀌어 확정값과 어긋났다
   (2606 마감 1시간 뒤 수정된 전표 실측). 소급은 **당월 소급조정**으로.

### 7-8. 컷오버 후 최종형
`nx.stock_ledger` 가 실시간 정본이 되면 수불장은 **기초 스냅샷 + 원장 델타**로 통일된다(§1 영구재고 모델).
그때 `mat_stock_daily`·레거시 임시테이블·재현 recipe 는 모두 은퇴한다. **지금 만드는 화면도 그 형태를 전제로 짜라.**
