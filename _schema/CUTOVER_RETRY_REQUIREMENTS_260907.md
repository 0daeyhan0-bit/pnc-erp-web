## ★ THE 원칙 — 단일 데이터셋 (모든 것의 상위)
**우리 프로그램은 하나의 데이터셋만 쓴다. 2 SET(미러+클린) 병행 운영은 없다.**
레거시 데이터를 우리쪽으로 이관 → 우리 프로그램이 **그 단일 이관본만** 단일 소스로 사용.

도메인 간 차이는 "단일이냐"가 아니라 **"형태 변환 여부"** 뿐:
- **일반 도메인** = 레거시 형태 **그대로 이관**한 단일본.
- **BOM 관련 모든 테이블**(bom_header/bom_line 등 BOM 계열 전부) = copy가 아니라 **데이터 형태(스키마) 자체를 우리 방식으로 변환**한 단일본(레거시와 스키마가 전혀 다름). **이미 완료**. 형태가 달라 레거시와의 차이는 **sync로 맞추는 방식**을 택함.

→ 어느 경우도 단일. 현재 dual-table 병존(아래)은 **이 원칙 위반**.

## ★ 재컷오버 전제조건 — 사전 전부 수정
**이 원칙과 관련된 프로그램은 컷오버 "전에" 전부 수정 완료해야 한다.**
미러 직독·이중 테이블이 남은 채 컷오버하면 이번처럼 또 실패한다. 컷오버 후 그대로 돌 코드여야 하며, **사후 수정은 없다.**

## 원칙 준수를 위한 세부 (①~④ · 전부 컷오버 전 완료 대상)

### ① 레거시 읽기 → nx 전면 반영
레거시 DB(`PARTNER_ERP.dbo`)를 읽는 **모든** 부분이 컷오버 때 nx 단일본을 읽도록 반영.
- **현황**: FLIP은 `dbo.`→`nx.`(데이터베이스)만 바꿈 → `nx.` 안의 **미러 테이블 직독 코드 ~194곳 잔존**(레거시 동결 시 옛값). 상세 = `MIRROR_CLEAN_DUAL_TABLE_AUDIT.md §6`.

### ② 데이터 이관 선행 → 일·월마감 우리쪽 수행 (2025년 1월부터)
레거시가 마감을 (완전히) 안 했으므로 **우리가 일마감·월마감을 직접 수행**.
- **★선행조건 = 데이터 이관 먼저.** 마감=f(전표/원장)이므로 **2501~현재 전표·원장이 nx에 온전히 이관**돼야 마감이 옳게 계산됨. → **①이관 완주 → ②그 위에서 일·월마감**.
- **진행 시작 = 2025년 1월(2501)** ~ 현재 완주.
- **현황**: 월스냅샷 `pu_t_month_stock_wh` 2607까지·**8월 없음**(레거시에도 없음). 일마감 `mat_stock_daily` 260906까지.
- 마감엔진 = `/api/close/run`(MAT/PRD/SAL · D/M) → `nx.stock_snapshot`+`nx.period_close`. 설계=`create_period_close.py`.

### ③ 음수재고는 우리 DB에 없어야 한다
단일본에 음수재고가 존재해선 안 된다.
- **현황**: 9월 자재입출고현황 음수 다수(재고합계 -176,924). 원인 = 8월 월스냅샷 부재로 bf=0(→②③④로 해결).

### ④ 마감 미완이어도 이전 시점으로 롤포워드 (모든 재고 프로그램)
일마감이 안 돼 있어도 **그 이전 시점(가장 최근 확정) 데이터를 읽어 계산**해 음수가 안 나오도록,
**모든 재고 관련 프로그램**(자재/생산/제품 입출고현황 등)을 수정.
- **현황**: 화면 로직(`live_api._matinout`)이 "직전월 스냅샷 필수" → 없으면 bf=0. 최근 가용 스냅샷부터 롤포워드로 개선.

### ⑤ 테이블 이관 대상/비대상 구분표 작성
**사용하지 않을 테이블까지 포함해, 전 테이블을 "이관할 것 / 이관 안 할 것(미사용)"으로 구분**한 표를 만든다.
- 목적: 단일 데이터셋 원칙 하에 무엇을 우리쪽으로 가져오고 무엇을 버릴지 명확히(불필요/미사용 테이블 이관 방지).
- 구분 축(안): 이관대상(그대로) / 이관대상(BOM식 형태변환) / 비이관(미사용·폐기) / 판단보류.
- 기준 자료: `CUTOVER_DELTA_INVENTORY.md`(미러82 등)·`MIRROR_CLEAN_DUAL_TABLE_AUDIT.md`·`DO_NOT_USE_FIELDS.md`(은퇴 등록부).
