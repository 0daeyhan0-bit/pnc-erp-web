# 조달프로파일 → 생산계획 → 자동발주 + 생산운영 통합 설계

> ⏸️ **보류 (2026-08-14)**: 사용자 판단 "방향이 아닌 것 같다 · 너무 어려워 추후 설계". **아래는 확정 아님 = 논의 스냅샷/출발점.** 재개 시 방향부터 재검토(특히 route_line 공정별 업체·넷팅 전제). 성급히 구현 금지.

작성 2026-08-14. 조달 프로파일(공정기반 route + 업체)을 **생산계획 시 자동발주 + 생산작업**으로 전개하는 정본 설계.

## 1. 문제 정의
- 조달 프로파일 = **공정 기반 후보(route)** + 배분. 협력사도 비율 가능.
- 남은 숙제: **생산계획 시 자동발주를 어떻게 보내나** + **생산 입장에서 서로 다른 공정(2공정)을 어떻게 운영하나**(조달업체는 생산에 안 중요).
- 공정후보도 나누고 업체도 나눠서 복잡해짐 → 정리 필요.

## 2. 사용자 확정 지침 (2026-08-14)
1. **1업체/공정**: 동일 품목에서 같은 공정을 동시에 2업체로 운영하지 않음. 특정 공정 = 업체 1개.
2. **route 비율은 품목마다 입력하지 않음**: 수백 품목을 계획 시점에 손으로 비율 거는 것은 불가.
3. **태국/국내 분할 = 넷팅(계획 결과)**: 프로파일에 고정비율 저장 안 함. 태국은 리드타임 길어 **수입 예정입고**가 선행 → 그걸 소요에서 차감, 잔량 국내. **현재 태국 예정입고 데이터 없음.**
4. **태국(FONE)도 한국서 일부 작업**: R01(태국)도 사내공정 있음(완성품 매입 아님).

## 3. 핵심 모델 — 3개념 구분 (혼동 금지)
| 개념 | 정의 | 수량 |
|---|---|---|
| **route (조달경로)** | 한 품목을 만드는 **하나의 방법 = 공정 시퀀스** | — |
| **route_line** | route 안에서 **공정마다 담당(사내\|업체)**, 순서 | — |
| **route 배분** | 여러 route에 **수량 분할**(대안) | 나눔 |

**3가지 배치:**
- **직렬(다공정·다업체)**: 한 route, 공정마다 다른 업체, **전량 통과**. 예: 절삭→미래, 용접→명진.
- **병렬(분할)**: 여러 route, **수량 분할**. 예: R01 태국 / R02 국내(명진).
- **금지**: 같은 공정을 여러 업체(병렬) — 지침 1로 배제.

## 4. ★통합 자동발주 엔진 (하나의 엔진, 태국 특별취급 아님)
```
순소요 Q
 → [route 분할]  (분할 있으면 나눔 / 없으면 전량 단일 route)      ← 태국만 여기 관여(넷팅)
 → route별 [공정 시퀀스 전개]
     · 외주 공정 → 그 공정의 업체에 발주(PO) + 사급출고             ← 한국·태국 공통(동일 코드)
     · 사내 공정 → 생산 작업지시
```
- **"공정→업체 발주"는 직렬·병렬 둘 다 동일.** 태국은 앞에 "수량 나누기 한 단계"만 추가.
- 태국 예정입고 없으면 분할 스텝 비활성 → **전 품목 단일 route 전량** = 지금 동작과 동일.

## 5. 생산 운영 (2공정) — 업체 무시, 공정만
- 품목 사내작업 = **Σroute(route량 × 그 route의 사내공정 ST)**.
- R01(태국): 사내 마무리ST × R01량 / R02(명진): (절삭+마무리)ST × R02량.
- 직렬(미래+명진): 사내 마무리만 전량, 나머지는 사급.
- **사급 흐름(순차 체인)**: 소재 → 사급출고 → 외주공정 → 입고 → (다음 외주 or 사내) → 완제품. **공정 경계마다 사급출고/입고 전표 자동. 업체 1개/공정 = 재고점 1:1.**
- 생산은 업체를 몰라도 되고 **공정 순서(사내/외주 시퀀스)만** 운영.

## 6. route 배분 = 계획시점 넷팅 (입력 0)
- 프로파일 = route 정의(공정분담·업체)만, **비율 컬럼 없음/미사용**.
- 태국(R01) = 태국 수입 예정입고량(그 품목·기간) ← 자동. 국내(R02) = Q − 태국예정 ← 잔량 자동.
- 표준 MRP 넷팅: `순소요 = 총소요 − 재고 − 예정입고(태국)`. 비율은 사후 계산될 뿐 아무도 입력 안 함.
- **현재 태국 예정입고 없음** → 넷팅 소스 없음 → 전량 국내 단일 route.

## 6-1. ★생산계획은 롤링(전면 재생성) — 재도출 원칙
사용자(2026-08-14): **생산계획이 다 바뀌는 구조.** LG수요 변동 → 매 회차 MPS/MRP 전면 재계산.
→ 따라서 **route 배분·발주·생산작업은 "고정 저장값"이 아니라 매 회차 현재 facts로 재도출**해야 함(넷팅). 이게 §6 넷팅 방식이 맞는 근본 이유:
- **고정 비율 저장 금지** — 다음 회차에 stale.
- **매 회차 재도출**: `순소요 = 총소요(신규계획) − 재고 − 기발주(이미 나간 PO) − 예정입고(태국)` → 그 결과로 신규/추가 발주분만 산출.
- **기발주 넷팅**: 이미 발송된 PO는 총소요에서 차감 → 재계획해도 **중복발주 안 남**(과/부족만 델타 발주).
- `plan_route_alloc`은 저장하더라도 **그 회차 스냅샷(추적·손익·재현)** 용이지, 다음 회차 입력이 아님.
- 즉 **엔진은 상태를 안 들고, 매번 현재 데이터로 순수 재계산**(idempotent) → 계획이 다 바뀌어도 안전.

## 7. 스키마 (설계, 미구현)
- **route_line**(신설/확장): `(route_id, seq, proc_code, 담당[사내|업체], 업체코드)` — route의 공정별 담당 정의. **자동발주=외주행, 생산=사내행, 사급=사내↔업체 전환 지점.**
- **plan_route_alloc**(신설, Phase2): `(계획ID, 품목, route_id, 배분량)` — 회차별 넷팅 결과 기록(추적·재현·손익).
- **태국 예정입고**(신설, Phase2): 수입발주/선적 스케줄(품목·수량·입고예정일) — 넷팅 소스.
- 기존 재사용: nx.sourcing_route/_line/_proc/_weld, nx.sourcing_profile(업체·배분%), nx.order_vendor.

## 8. 현재 상태 (코드 실측 2026-08-14)
- **manorder.py(수동발주)**: 업체 배분율(sourcing_profile)만 자동적용(이 매입처 몫, 미설정=100%). **route_alloc(R01/R02 배분)은 어디에도 미적용**(주석 명시) → 정합 위해 미곱함.
- **autoorder.py(자동발주)**: 생산계획+주문→MRP→조달배분→업체별 PO. nx.plan_mat_source(배분% 적용 QTY) 사용. route_alloc 동일 미적용.
- → **현재 전 품목 사실상 단일 route 100%로 동작 = 지침(비율입력 없음)과 이미 정합. 지금 당장 문제 없음.**

## 9. 단계 (Phase)
| Phase | 내용 | 태국 데이터 |
|---|---|---|
| **1 (지금)** | 국내 단일 route + **공정별 업체 발주(직렬)** + 생산 사내작업 + 사급체인 | 불필요 |
| **2 (나중)** | 태국 수입 예정입고 입력 → 넷팅 오버레이(route 분할) | 그때 구축 |

## 10. 미결/확인 필요
- **[중요] 공정별 업체**: 현재 sourcing_profile은 **route 단위 업체**(공정별 아님). 직렬(미래 절삭/명진 용접)을 담으려면 **route_line에 공정별 업체** 확장 필요 → 스키마 §7 신설이 이 지점.
- 사급 재고점·전표 세부(공정 경계 WIP 이동) 설계.
- Phase2 태국 예정입고 소스(엑셀 인입 vs 수입발주 모듈 신설).
