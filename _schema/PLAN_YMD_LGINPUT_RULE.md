# 계획일(PLAN_YMD) 웹↔레거시 차이 = **설계 차이. 버그 아님** (2026-09-06 결론)

> ⚠ 이 문서의 초판은 "웹에 재배치 로직이 빠졌다"고 결론냈다. **그 결론은 틀렸다.**
> 아래는 정정본이다. 같은 조사를 반복하지 않도록 오판 경위까지 남긴다.

## 결론부터

웹은 계획일을 **자체 산식(라인당김)으로 계산한다**. 레거시 `PLAN_YMD` 를 베끼지 않는다.
이것은 **2026-08-27 의도적 결정**이며, 차이는 정상이다.

`backend/routers/planrev.py:1632` · `:2005`

```
⛔레거시 LG_INPUT_YMD/HM 채택은 삭제했다(2026-08-27). 웹은 레거시를 참조하지 않는다.
⛔레거시 값 채택 제거 — 웹 산식 결과를 그대로 쓴다.
```

## 왜 제거했나 — 대사 기준이 틀렸었다

실측(제번 `6I1M0BBK`):

| 화면 표시 | 실제 컬럼 | 값 |
|---|---|---|
| LG OUTPUT시간 | `ORG_PLAN_YMD` / `ORG_OUTPUT_HM` | 260827 11:35 (엑셀 원본) |
| **LG INPUT** | **`PLAN_YMD` / `OUTPUT_HM`** | 260827 07:50 ← 라인당김 결과 |
| (화면에 없음) | `LG_INPUT_YMD` / `LG_INPUT_HM` | 260825 18:05 |

**`LG_INPUT_YMD` 는 화면의 'LG INPUT' 이 아니다.** 이름만 비슷한 별개 컬럼이다.
종전엔 이걸로 `_py/_phm` 을 덮어썼는데, 대사 축이 틀렸던 것이라 끊었다.

## 내가 어떻게 오판했나 (2026-09-06)

협력사 자재계획현황 대사 중 행수가 1,795 vs 1,776 으로 달라 계획일을 팠고,
`PLAN_YMD = max(LG_INPUT_YMD, 기준일)` 이 **96.3% 적중**하는 걸 보고
"레거시가 이 규칙을 쓰는데 웹에 없다"고 결론냈다.

**높은 상관을 인과로 읽은 것이 오류다.** 레거시가 라인당김을 하면 결과가 LG 투입 근처로
수렴하는 게 자연스럽다 — 같은 라인 스케줄을 보고 계산하기 때문이다. 96.3% 는 그 부산물이지
레거시가 `LG_INPUT_YMD` 를 복사한다는 증거가 아니다.

★교훈: 웹에 "없어 보이는" 로직을 발견하면 **먼저 `planrev.py` 주석을 찾을 것.**
       의도적으로 뺀 것에는 대부분 이유와 실측 근거가 적혀 있다.

## 참고 — 실측해둔 수치 (조사 자체는 유효)

출발점이 같고 방식이 다르니 결과가 갈리는 것이 정상이다.
