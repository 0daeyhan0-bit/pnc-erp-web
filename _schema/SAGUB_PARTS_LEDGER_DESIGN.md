## 1. 모델 (자도번 사급부품 × 협력사, 2026-01~)
```
사급부품 수불장 = per (사급부품 자도번 d, 협력사 c)
  입고(+, 보낸것)   = Σ 사급출고(우리→협력사)                    [원천 아래 §2]
  출고(−, 소진)     = Σ (세트입고 완성수량 × 상위품 BOM 사급부품 소요)  [소요엔진 §3]
  잔량             = Σ입고 − Σ출고   (기초 0 @ 2026-01-01)
```
- **대상 = 사급부품**(BOM `SAGUB_FLAG='1'` 자식 = stop_set). 원소재(동관 7072AR*)는 **다음 프로그램(원소재 수불장)**, 여기서 제외.

## 2. 입고(+) = 사급출고 원천
- **실소스 = `PU_T_STOCK_MAINT` `MAINT_TAG='5'`(협력업체판매=사급출고)** — 2026년 14,607행·51협력사·718자도번(실측 2026-08-29). 불출=음수저장 → 협력사 보유는 +abs(qty).
  - 근거 = SAGUB_OUTPUT_PROGRAMS_ANALYSIS §5.8(역분석 확정: 판매및출고등록 저장처=PU_T_STOCK_MAINT tag5).
  - 부품 필터 = 자도번이 stop_set(사급부품) 소속인 행만(원소재 7072AR* 자동 제외).
- ★런타임 하드룰: 화면은 **클린 nx 원장**을 읽는다. 그래서 tag5(2026-01~)를 **nx 사급 원장으로 1회 인제스트**(=수불데이터 작성 시작), 이후 신규 사급출고는 nx가 기록. (레거시 PU_T_STOCK_MAINT 직독은 빌드 전용, 화면 아님.)
- nx.saleout_maint tag5는 현재 9행뿐(테스트) = 실데이터 미이관 → 인제스트 필요.

## 3. 출고(−) = 세트입고 소진 (소요엔진)
- **세트입고**(nx.set_input_req, in_ymd≥260101) 각 송장: item_code=완제품(모도번)·in_cust=협력사·수량.
- **소진 = 완성수량 × `sagub_parts_soyo(완제품, stop_set)`** (nx_soyo_engine §10, v_pr_bom except≠1 재귀, stop_set 도달 계상·정지, 용접봉 제외). → {사급부품 자도번: 소요개수}.
- 협력사 = 세트입고 in_cust. → per (in_cust, 사급부품, in_ymd) 소진(−).
- ★ad-hoc BOM 전개 금지(변형SUB 이중계상). 반드시 엔진.

## 4. stop_set (사급부품 universe) + 용접 제외
- = `nx.v_pr_bom`에서 `SAGUB_FLAG='1'`인 distinct child item_code(600종). (레거시 SAGUB_FLAG 대응.)
- **★용접 소재는 별도 트랙 = 제외**(사용자 2026-08-29 "용접봉은 별개야"): 용접봉(RAC*)·용접링/은납(BCUP*, item_name '1%용접링')·이름 '용접' 포함 233종 → 입고·소진 양쪽에서 제외. (용접봉/용접링 정산은 별도 프로그램.)

## 5. 화면 (협력사 > 사급 수불장, 신규)
- 좌 = (협력사·자도번) 현황: 기초0·입고(보낸것)·출고(소진)·잔량. 필터: 협력사·자도번·기간·(+/−/0)잔량.
- 우 = 선택 (협력사×자도번) 수불이력: 일자·구분(사급출고/세트소진/조정)·입고·출고·running balance.
- 레거시 080(사급재고입출고현황) 골격 계승하되 **데이터는 우리 재구축**(레거시 정본에 안 맞춤).
