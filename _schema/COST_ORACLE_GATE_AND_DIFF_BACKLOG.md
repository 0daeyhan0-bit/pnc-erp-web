## 1. 왜 이 과제가 생겼나

`sagub_whole` 소스 리포인트(PR #125)를 검증하다가 **검증 장치 자체의 결함**을 발견했다.
대표 지시 "검증은 전체적으로 다 해야 한다 · **전수 검사가 기본 규칙**" 에 따라 전수로 돌린 결과다.

## 2. 발견 2가지

### 2-1. ★`cost_oracle.py anchors` 는 **엔진을 대조하지 않는다** (게이트 결함)

`anchors` 가 찍는 `✓` 는 **레거시 SP 자기 자신의 성분식 검산**이다:
```
재료 + 가공 + 일반 + 운반 + 이윤 = 실원가   ← SP 내부 정합성만 본다
```
**nx 엔진 값과 비교하는 코드가 없다.** 즉 지금까지 "앵커 통과 = 원가 diff0" 로 읽어온 것은
근거가 없었다. `§1-5` 의 diff0 하드룰이 **실제로 지켜지는지 한 번도 전수 확인된 적이 없다.**

### 2-2. 엔진 ↔ 레거시 SP 재료비 불일치 (전수 진행 중)

`pncind` 계정을 확보해 처음으로 실제 대조를 돌린 결과:

| 범위 | 결과 |
|---|---|
| 시범 200종 | 일치 178 · **불일치 22**(11%) · 예외 0 |
| 전수 6,550종 (2026-08-31 야간, **3,000종 시점 중단 기록**) | 일치 2,621 · **불일치 379**(12.6%) |

**차이의 성격이 두 갈래로 보인다** (분류가 이 과제의 첫 작업):

```
① ±3원 · ±2.4원 · ±1.8원 …  반올림 수준으로 보이는 다수
   예) 5211A10678F  SP 1,303.00 / 엔진 1,297.00  (−6.00)
       5211A00011P  SP 14,254.07 / 엔진 14,257.07 (+3.00)

② 실질 차이
   예) AJR30077403  SP 26,149.00 / 엔진 26,437.00 (+288)   ★앵커 품목인데 벌어진다
```

### 2-3. ★이 불일치는 **오늘 작업과 무관한 기존 상태**다 (확인 완료)

변경 전/후 엔진을 각각 로드해 직접 대조했다 — **완전히 동일**:
```
                 변경전        변경후
AJR75563402     4,190.59     4,190.59
AJR75563503    21,232.00    21,232.00
AJR30077403    26,437.00    26,437.00   ← SP 는 26,149. 변경 전부터 벌어져 있었다
```
그리고 `sagub_whole` 리포인트 자체는 **전수 6,550종 불일치 0 · PASS**(합계 60,195,797.98 동일).
⟹ **PR #125 는 안전하다. 배포해도 된다.**

## 6. 함께 남기는 검증 교훈 (같은 실수 반복 금지)

- **표본은 검증이 아니다.** 60종 표본으로 "검증 완료" 보고 → 대표 지적. **전수가 기본 규칙.**

## 7. 군집 A 규명 완료 — `nx.bom_line` 플래그가 원천과 **뒤바뀌어 있다** (2026-08-31)

### 7-1. 대상
`AJR30007102` (군집 A 5종 중 하나 · 차이 **+7,710.99**)

### 7-2. 실측 — 소스별 자식 행

| 소스 | `MJX62771704` | `MJX62771713` |
|---|---|---|
| **`PARTNER_ERP.dbo.CS_M_ITEM_BOM`** (레거시 원가 원천 · SP 가 씀) | **행 자체가 없음** | `cs_calc_except=0` → **계상** |
| **`nx.bom_line`** (우리 원가엔진이 씀) | `cs_calc_except=0` → **계상** | `cs_calc_except=1` → **제외** |

**정확히 반대다.**

### 7-3. 그래서 금액이 이렇게 갈린다
```
SP    : 713 계상 → 713 단가 0 원        → 재료비 41,734.50
엔진  : 704 계상 → 704 단가 7,712 원    → 재료비 49,445.49
차이  : +7,710.99  ≈  704 단가 7,712
```
엔진 노드를 뜯어 확인: **엔진에만 있는 코드 = `MJX62771704` 7,712.00** / **SP 에만 있는 코드 = `MJX62771713`**.

### 7-4. 엔진 로직은 잘못이 없다
원가엔진은 `nx.bom_line` 을 **`cs_calc_except` 로만** 거른다(`EXCEPT_FLAG` 는 안 본다).
이는 레거시 SP 와 **같은 규칙**이다(SP 도 CS_CALC_EXCEPT 기준). 즉 **로직이 아니라 데이터가 어긋났다.**

### 7-5. ★어제 해석 정정
어제 "레거시 역전개가 704 를 41곳만 보여주는 건 `EXCEPT_FLAG=1` 을 걸러서" 라고 했는데 **틀렸다.**
실제로는 **`CS_M_ITEM_BOM` 에 그 5개 Assy 의 704 행이 애초에 없다.**
`PR_M_ITEM_BOM` 계열(→`nx.v_pr_bom`·`nx.bom_line`)에만 있는 행이다.
⟹ **레거시 두 BOM 테이블이 서로 다르다**(원가용 CS vs 생산/BOM용 PR).

### 7-6. 성격 = 이미 등재된 미러 부채
`nx.bom_line` 은 레거시 CS BOM 의 미러다(`BOM_MIRROR_DEBT_AND_DIFF0_PRINCIPLE.md`).
그런데 **원천에 없는 704 행이 들어와 있고 `cs_calc_except` 값도 반대**다.
`CS_CALC_EXCEPT_HANDOFF.md` 가 경고한 위험 —
*"`/api/bom/save` 는 전체 DELETE 후 재INSERT라 payload 에 플래그가 빠지면 조용히 0 으로 리셋된다"* —
의 실제 사례로 보인다. **편집 저장이 플래그를 날린 흔적**을 의심할 것.

### 7-7. ☐ 남은 확인 (수정 전)
1. 5개 Assy(`AJR30007102`~`06`) 전부 같은 모양인지
2. 같은 형태(원천에 없는 행 + 플래그 반전)가 **전 BOM 에 몇 건인지** — `nx.bom_line` vs `CS_M_ITEM_BOM` 전수 대조
3. 그 중 `LEGACY_BUG_CANDIDATES.md` 의 승인된 버그수정인 것이 있는지
4. **고치는 방향** — 미러를 원천에 맞출 것인가(diff0 회복), 아니면 우리 BOM 이 맞고 CS 가 낡은 것인가.
   ★`nx.bom_line` 은 다른 프로그램(소요·계획)도 쓰므로 **함부로 바꾸면 안 된다**. 영향 먼저.

## 13. ★§12 정정 — "용접봉 차이는 전부 정상"은 성급한 일반화였다 (2026-08-31)

### 13-1. 무엇이 틀렸나
§12 에서 `nx_cost_engine.py:143/152` **코드 한 줄만 읽고**
"용접봉(RAC*) 5,103건 차이는 설계상 정상" 이라고 단정했다.
대표 지적("성급한 일반화는 금물 · 철저하게 검증") 후 **데이터로** 확인하니 틀렸다.

### 13-2. 철저 검증 6방향 (`_migration/audit_weld_coverage.py`)
용접봉의 정본 대조축은 `bom_line` 이 아니라 **`CS_M_ITEM_BOM ↔ nx.proc_weld`** 다.

```
CS_M_ITEM_BOM(RAC) 5,518 · nx.bom_line(RAC) 419 · nx.proc_weld 5,516
```

| 방향 | 건수 | 판정 |
|---|---:|---|
| ① CS 에 있는데 `bom_line`·`proc_weld` **둘 다 없음** | **3** | ★진짜 누락 |
| ② CS ↔ `proc_weld` **수량 다름** | **1** | ★결함 |
| ③ `proc_weld` 에만 있음(CS 원천 없음) | 3 | 별도 판단 |
| ④ `bom_line` 에 남은 RAC 잔재 | 419 | 무해(엔진이 `NOT LIKE 'RAC%'` 로 거름) |
| ⑤ 세 곳 모두 존재 | 413 | ④의 부분집합 — **이중계상 아님** |
| ⑥ `cs_calc_except` 차이 | **0** | 없음 |

⟹ **용접봉 실제 결함 = 4건**(①3 + ②1). "전부 정상" 이 아니었다.

### 13-3. ★그 4건이 §11 의 미규명 건을 설명한다
| 품번 | §11 차이 | 원인(이번에 규명) |

| **`AJR30077403`** | **+288** | ②용접봉 **수량 불일치** — 아래 실측 |

AJR30077403 (앵커 품목)

- **코드를 읽고 "정상"이라 단정하지 말 것.** 설계 의도가 맞아도 **데이터가 그 의도대로인지는 별개**다.
