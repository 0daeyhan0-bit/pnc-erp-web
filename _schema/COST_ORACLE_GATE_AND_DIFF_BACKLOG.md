## 1. 왜 이 과제가 생겼나

`sagub_whole` 소스 리포인트(PR #125)를 검증하다가 **검증 장치 자체의 결함**을 발견했다.
대표 지시 "검증은 전체적으로 다 해야 한다 · **전수 검사가 기본 규칙**" 에 따라 전수로 돌린 결과다.

## 2. 발견 2가지

### 2-1. ★`cost_oracle.py anchors` 는 **엔진을 대조하지 않는다** (게이트 결함)

`anchors` 가 찍는 `✓` 는 **레거시 SP 자기 자신의 성분식 검산**이다:
```
재료 + 가공 + 일반 + 운반 + 이윤 = 실원가   ← SP 내부 정합성만 본다
```
**nx 엔진 값과 비교하는 코드가 없다.** 즉 지금까지 "앵커 통과 = 원가 diff0" 로 읽어온 것은
근거가 없었다. `§1-5` 의 diff0 하드룰이 **실제로 지켜지는지 한 번도 전수 확인된 적이 없다.**

### 2-2. 엔진 ↔ 레거시 SP 재료비 불일치 (전수 진행 중)

`pncind` 계정을 확보해 처음으로 실제 대조를 돌린 결과:

| 범위 | 결과 |
|---|---|
| 시범 200종 | 일치 178 · **불일치 22**(11%) · 예외 0 |
| 전수 6,550종 (2026-08-31 야간, **3,000종 시점 중단 기록**) | 일치 2,621 · **불일치 379**(12.6%) |

**차이의 성격이 두 갈래로 보인다** (분류가 이 과제의 첫 작업):

```
① ±3원 · ±2.4원 · ±1.8원 …  반올림 수준으로 보이는 다수
   예) 5211A10678F  SP 1,303.00 / 엔진 1,297.00  (−6.00)
       5211A00011P  SP 14,254.07 / 엔진 14,257.07 (+3.00)

② 실질 차이
   예) AJR30077403  SP 26,149.00 / 엔진 26,437.00 (+288)   ★앵커 품목인데 벌어진다
```

### 2-3. ★이 불일치는 **오늘 작업과 무관한 기존 상태**다 (확인 완료)

변경 전/후 엔진을 각각 로드해 직접 대조했다 — **완전히 동일**:
```
                 변경전        변경후
AJR75563402     4,190.59     4,190.59
AJR75563503    21,232.00    21,232.00
AJR30077403    26,437.00    26,437.00   ← SP 는 26,149. 변경 전부터 벌어져 있었다
```
그리고 `sagub_whole` 리포인트 자체는 **전수 6,550종 불일치 0 · PASS**(합계 60,195,797.98 동일).
⟹ **PR #125 는 안전하다. 배포해도 된다.**

## 6. 함께 남기는 검증 교훈 (같은 실수 반복 금지)

- **표본은 검증이 아니다.** 60종 표본으로 "검증 완료" 보고 → 대표 지적. **전수가 기본 규칙.**
- **공허한 검증을 조심하라.** 메서드명을 `sagub_amt`(실제는 `sagub_whole`)로 잘못 써 전부 예외가 났는데,
  예외 문자열끼리 비교돼 **"불일치 0 = PASS"** 로 보였다. **값이 실제로 나오는지 먼저 확인할 것**
  (값이 0 아닌 품목 수를 같이 출력하면 바로 드러난다 — 두 전수 스크립트에 그렇게 넣어 뒀다).
- **게이트가 무엇을 대조하는지 읽어라.** `✓` 가 찍힌다고 대조된 게 아니다(§2-1).
