# 재고 flow(자재→키팅→생산→완성/영업) 수불장 in/out 검증 — 2026-08-24 야간

> 사용자 지시: "자재입고→자재재고→키팅→생산재고→생산실적→영업재고 구조가 **실제 프로그램으로** 그렇게
> 이뤄지는지, 그리고 **각종 수불장에 값이 잘 들어오고 나가는지** 검증. 조정·입고·출고·삭제·이동 등 프로그램 다수."
>
> 방식: **실제 엔드포인트 함수**를 `_nx`/`_nx_tx` 몽키패치로 **단일 롤백 트랜잭션(no-commit 공유커넥션)** 에 묶어 구동
> → 수불장/재고/원장 델타 측정 → 마지막 `ROLLBACK`. **공유 nx DB 오염 0**(172,283행 불변, 3회 재확인).
> 하네스: `scratchpad/flow_verify_all.py`·`flow_verify_v2.py`·`flow_verify_rollback.py`.

---

## 1. 재고점(STOCK_POINT) 모델 = 단일원장 nx.stock_ledger
`MAT`(자재재고) → `RDY`(준비/키팅) → `PRD`(생산재고·반제품) / `ASY`(제품재고=영업) · `SAG`(사급) · `MV`(창고간이동, MAT)
- 잔량 = 원장 `SUM(MAINT_QTY)` 파생(이중기입 아님). 입고=+, 출고=−.

### 역대칭(취소·삭제 → 0 복귀) 전부 통과
- 키팅 확인+취소 = RDY net 0 · 자재이동+삭제 = MAT net 0 · 생산조정+삭제 = PRD net 0 · 백플러시 post+reverse = 생산품 net 0.

### 재고게이트(마이너스 원천차단) 통과
- 자재출고/반품: `가용(_mat_avail=mat_stock_daily) < 수량` → 거부.
- 백플러시: BOM 소요 > 자재현재고면 "자재부족으로 생산실적 불가" 거부(키팅 무관·자재로만 판정).

## 3. ★발견된 결함(FINDINGS)

### F1. (확정) `stock_update`·`stock_delete` 미러 미반영 → 자재수불장·자재재고 불일치
- `stock_save`(조정/입고/출고)는 **3곳(stock_ledger + PU_T_STOCK_MAINT + PU_T_MAT_STOCK_WH)** 동시 반영.
- 그러나 **`stock_update`(수정)·`stock_delete`(삭제)는 `nx.stock_ledger`만** 수정 →
  - 자재수불장(PU_T_STOCK_MAINT): 수정 전 원본행·삭제된 행이 **그대로 남음**.
  - 자재재고(PU_T_MAT_STOCK_WH): 잔액이 **수정/삭제분만큼 어긋남**.
- 실증: 입고+100(3곳 일치) → 수정 100→150(원장 +50, 수불장/재고 **0**) → 삭제(원장 −150, 수불장/재고 **0**).
- 영향: 사용자가 입고/조정을 **수정·삭제하면** 원장(준비등록 팝업 등)과 자재수불장/입출고현황/재고잔액이 **갈림**.
- 수정안(제안·미구현): `stock_save`의 미러 반영 블록(코드 line ~119~156)을 `stock_update`/`stock_delete`에도 적용
  (수정=구값 −/신값 +, 삭제=원장부호 반대로 미러 되돌림 + PU_T_STOCK_MAINT 상쇄행 or 삭제).

### F2. (확정) 자재반품(`return`/RT) — 자재재고는 반영, 자재수불장 미반영(부분갭)
- 실증(격리): 반품 15 → 원장 −15 ✅ · **자재재고(PU_T_MAT_STOCK_WH) −15 ✅** · **자재수불장(PU_T_STOCK_MAINT) +0·RT행 0개 ❌**.
- 원인: PU_T_STOCK_MAINT 로의 `RT` 태그 INSERT가 실패하는데 `try/except pass`로 **은폐**(잔액은 맞고 입출고 내역엔 반품이 안 잡힘).
- 수정안: PU_T_STOCK_MAINT의 MAINT_TAG 허용값/컬럼 제약 확인 → RT 매핑(or 유효 태그로 치환) 후 propagate 성공시키기. `try/except pass`가 결함을 삼키므로 로깅 필요.

### F3. (아키텍처) 단일원장 생산/완성 전이가 **운영(공유 nx)엔 미가동**
- 공유 nx.stock_ledger: `MAT 172,259행`·`RDY 14행(키팅 테스트뿐)`·**`PRD 0`·`ASY 0`·`backflush_log 0`**.
- 즉 키팅→생산실적(백플러시)→완성/출하 단일원장 전이는 **dev(localhost) 전용**이며 운영 데이터에선 아직 안 돎.
- 현재 조회화면 원천: 생산재고조회/제품재고조회 = **레거시미러(SA_T_ITEM_STOCK)**, 자재수불장 = **PU_T_STOCK_MAINT / mat_stock_daily(이동평균)**. 우리 단일원장은 병행(미승격).
- ⟹ "실제로 그렇게 이뤄지는가"의 답: **설계·엔드포인트는 완비(검증상 정상 동작)되어 있으나, 운영 재고흐름의 정본은 아직 레거시미러**이며 단일원장 전면가동은 컷오버 과제.

## 4. 결론
- 자재 3대 쓰기(조정·입고·출고)의 **수불장 in/out은 정확**(원장·수불장·재고 3곳 일치, 부호·게이트 정상).
- 키팅·이동·생산조정·백플러시·출하 posting/역대칭 **전부 정상**, 마이너스 게이트 동작.
- **즉시 손봐야 할 것 = F1**(수정/삭제 미러 미반영) — 사용자 편집 시 자재수불장/재고 어긋남. F2(반품)도 함께.
- F3는 컷오버 로드맵(단일원장 승격) 사안.
