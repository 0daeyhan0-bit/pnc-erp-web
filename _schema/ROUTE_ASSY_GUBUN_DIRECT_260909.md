# 조달후보 최상위 ASSY 구분·업체 — 직납품이 편성에 안 잡히는 문제 (2026-09-09)

> 대표 지시. 순서 = **①레거시에 지정된 업체를 보여준다 → ②수정할 수 있게 한다 → ③조달후보 등록에서 고를 수 있게**
> → ④그래야 직납품이 「⑤자재소요·조달 편성」을 타고 협력사 계획에 나온다.
> 이 문서 = ①②③ 구현·검증 기록. **④는 미착수(승인 대기)**.
> 연계 정본: `ROUTE_REFLECTION_DESIGN.md`(구분 5종 확정·재매핑 정답소스) · `PLAN_PROGRAM_MASTER.md`

---

## 0. 대표가 짚은 것 (원문 요지)

- 조달 프로파일의 이 건은 **대원산업 직납품**인데 **대원산업을 등록할 수가 없다**.
- **R01(현행)은 「현행 보호」라 수정 버튼이 없다.**
- R02를 만들었더니 **SUB는 제작/외주 등을 고를 수 있는데 ASSY 기준으로 `외주직납`을 고를 수가 없다.**
- **직납품은 협력사 계획에 나와야 하는데 안 나온다.**
- **레거시에는 지정이 되어 있는데** 신규는 그 지정된 업체조차 확인할 수가 없다.
- ⑤ 자재소요계획이 `IN_CUST` 기준으로 편성되는데 **조달프로파일 등록 매입처 기준**이어야 한다.

## 1. 실측으로 확인한 현황

### 1-1. 레거시는 어디에 지정을 갖고 있나 — **견적원가조회 `w_cs_esti_010`**

```
AJJ30041801  Supporter Assembly   생산구분 2:외주   구매업체명 대원산업
AJJ30041801-SUB  체결-SUB          생산구분 1:사내
```

**그 값은 신규에도 이미 있다.** 없는 게 아니라 **화면이 안 그리고 있었다.**

| | 레거시 화면 | 신규 `nx.item` |
|---|---|---|
| 생산구분 | 2:외주 | `make_type=2` |
| 구매업체명 | 대원산업 | `in_cust=2148` |

정본 `ROUTE_REFLECTION_DESIGN.md` 에도 이미 적혀 있다 —
*"재매핑 정답 소스 = 레거시 견적BOM의 생산구분 + 거래처"*, *"구분 = make_type 5-way(제작1/외주2/구매3/사급4/외주직납5)"*.

### 1-2. 왜 ASSY 를 못 고르나

`screens.dev.js` `nodeBox()` 가 구분 드롭다운을 **`dsub>0`(SUB 노드)일 때만** 그렸다.
레벨0 ASSY(`dsub===0`)에는 아무것도 없었다. **저장 컬럼은 이미 있었다** —
`nx.sourcing_route.gubun` · `vendor_code`(헤더=ASSY 레벨).

### 1-3. 왜 발주업체·배분 팝업에도 없나

팝업 목록은 `order_soyo(품번)` 으로 만든다 — 이 함수는 **그 품번의 자식만** 돌려준다.
그래서 `AJJ30041801` 자신은 목록에 없고 자식 7개만 나온다. (`nx.order_vendor` = **0행**)

### 1-4. 편성(⑤)이 조달경로를 안 본다

```
지금 : ov_wc = routing_edge.wc → work_code → in_cust      (planrev.py `nx.item_ov`)
```
조달경로·조달프로파일이 이 식에 **없다**. 셋 다 비면 작업처가 빈칸이 되고 그 행은 협력사 계획에서 사라진다.

**실측**: 작업처 빈칸 **3,943행 · 223품목**(그중 lv0=직납 204품목).
단, 이 223품목은 **레거시도 213개가 비어 있고** 대부분 `5211A10305E-S6-3`·`티그용접` 같은 SUB/가상 품번이었다
— 대표가 지목한 건과는 다른 집합일 수 있어 ④ 착수 시 재확인 필요.

### 1-5. 편성을 직접 돌려 본 결과 (2026-09-09 18:12~18:13)

「생산계획업로드 → ④파트별 계획생성 → ⑤자재소요·조달 편성」을 실제로 실행했다.

```
STEP6 57.5초  part_lines 22,207
STEP7 45.3초  mat_lines 119,186
직납품 자재소요 반영 : 신규 153/153 · 레거시 82/82 · 레거시에만 있는 것 0
AJJ30041801          : 신규 lv0 17행·작업처 2148 = 레거시 17행·작업처 2148 (동일)
```
⟹ **현재 데이터에서는** 직납이 자재소요에 들어간다(`_step7_sql` 의 「직납품 앵커」 = 파트별계획에 노드 없으면 직납).
대표는 "지금 프로그램 기준으론 안 나온다"고 하셨으므로, **④ 착수 시 어느 화면에서 빠지는지 먼저 특정**해야 한다.

## 2. 구현 (①②③)

### ① 레거시 지정 표시 — `sourcing.py /api/sourcing/route/detail`

헤더 응답에 seed 4개 추가. **경로에 지정이 있으면 그것이 우선**, 없으면 품목마스터(=레거시 견적원가조회와 같은 값)를 보여준다.

```
gubun_seed        make_type → 제작/외주/구매/사급/외주직납
make_type         원값
vendor_seed       in_cust
vendor_seed_name  거래처명
```

### ② 수정 저장 — `sourcing.py /api/sourcing/route/gubun` (신설)

`nx.sourcing_route.gubun`(+선택적 `vendor_code`) 갱신. 편집이므로 **승인 리셋**(라인 구분과 같은 규약).
**새 테이블 없음** — 있는 컬럼을 쓴다.

★**허용값에 라벨 2벌을 모두 넣었다.** 이 컬럼엔 조달프로파일 라벨이 이미 들어 있다(기존 7행 전부 `자체`).
검증 중 `자체` 를 못 넣어 **원복이 실패한 실측**이 있었다.

| 계열 | 라벨 |
|---|---|
| 조달후보 라인(화면 드롭다운) | 제작 / 외주 / 구매 / 사급 / 외주직납 |
| 조달프로파일(`planrev._MKMAP`) | 자체 / 외주가공 / 매입 / 유상사급 / 외주완성 |

### ③ ASSY 구분 드롭다운 — `screens.dev.js` `nodeBox()`

`dsub===0` 일 때 `assyGubunCell()` 을 그린다 — 구분 5종 select + 업체명 + **`레거시` 배지**
(배지 = "아직 이 경로에 지정 안 함, 품목마스터를 보여주는 중").
프로파일 라벨은 `_G5` 로 5종에 맞춰 표시(`자체`→`제작` 등). 안 맞추면 `자체` 가 어느 옵션과도
안 맞아 첫 항목(제작)이 선택된 것처럼 보인다.

## 4. ☐남은 것 = ④ 편성 반영 (미착수·승인 대기)

```
지금 : ov_wc = routing_edge.wc → work_code → in_cust
안   : routing_edge.wc → **조달후보 지정(gubun·vendor)** → work_code → in_cust
```

**착수 전 확인할 것**
1. **어느 화면에서 직납이 빠지는지 특정**(§1-5 — 현재 측정으로는 자재소요·협력사계획현황 둘 다 나옴).
2. 우선순위 — `routing_edge.wc` 다음인지, 맨 앞인지(대표 확인 필요).
3. **지정이 없을 때 기존과 diff0** 증명 후 적용(실측상 프로파일≠편성 품목은 3개뿐이라 회귀 여지는 작다).
4. `nx.order_vendor` 가 0행인 이유(아직 미사용 vs 저장 불가) 확인 — 발주업체·배분 팝업에 ASSY 행 추가 여부와 연결.
